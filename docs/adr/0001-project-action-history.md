# Project Action History

**Status: accepted.** Project changes enter through `Project::apply(DawAction)`. Each successful action is recorded as a canonical internal event; a transaction is applied against a candidate state and committed as one history entry only when every child action succeeds. Undo/redo applies inverse/forward events, and track IDs are monotonic across undo so IDs from discarded redo branches are not reused. The history and its cursor are in-memory session state, not an append-only project log. Storage saves a validated project snapshot of the current state; loading restores that state with a fresh undo/redo history. The initial in-memory implementation clones track state to provide atomicity; this work stays off the audio callback, and the implementation can later move to persistent snapshots without changing the `Project` interface if profiling warrants it.
