# MIDI Contents Nudge during a linear tempo ramp

This Linux REAPER `7.82/linux-x86_64` / Default 7 probe extends the stepped-tempo fixture with one selected five-second loop-source MIDI item at 3.900 seconds. The tempo map starts at 120 BPM with linear-to-next enabled and reaches 60 BPM at the start of measure 3. REAPER reports that endpoint at 5.333333 seconds. The 250 ms Nudge interval starts inside the ramp and remains inside it.

The actual Nudge/Set Items window was set to `Nudge`, target `contents`, `250 milliseconds`, and Snap off. Main action 41249 changed `D_STARTOFFS` from 0 to 3.041994609 seconds. `MIDI_GetPPQPosFromProjTime` reports source phase 0 before the action and 4537.985 PPQ afterward in a 4984.900 PPQ loop, so the right nudge wraps backward by 446.915 PPQ. Action 41250 reaches the loop endpoint at 4985.000 PPQ. The item remains at 3.900 seconds with a five-second length; both source notes, loop flag, and selection remain unchanged. The project state-change counter stayed at zero.

For reference, the project-time interval from item start to 250 ms later maps to 298.875 PPQ in the native source-time query, while the Nudge action wraps the source phase by 446.915 PPQ. AAADAW now converts source phase through the active Tempo Map for this linear-ramp case and applies right/left Nudge in source-time direction. The App regression produces phase 4531 PPQ against the native 4537.985 PPQ; the 6.985 PPQ difference comes from AAADAW's integer 4974-tick source loop versus REAPER's 4984.900 PPQ query. This case is directionally aligned, but exact source-loop/timebase precision remains open.
