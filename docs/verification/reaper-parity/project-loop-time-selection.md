## AAADAW 当前实现

Timeline 维护单独的 `time_selection`、`loop_points` 与 `loop_points_linked` 状态。Loop points 允许零长度，以保留原厂在编辑光标越过另一端后的折叠结果。默认链接开启；通过现有选区手势更新 Time Selection 时，链接状态会同步 Loop points；设置端点或代码层设置 Loop points 时也按相同规则同步 Time Selection。Action List 加入 40222/40223、40621/40622/40623/40624/40632/40633/40634/40635、40020 对应操作，40222/40223 分别默认绑定 `{`/`}`，40621 的 `State` 列显示当前链接状态，40632/40633 在 Loop points 存在时分别定位到范围起点/终点；40020 的 Escape 行为通过全局取消路径清除两种范围。

引擎 `Transport` 现可持有非空的半开样本区间，并通过调用方预分配的 `TransportBlockSegment` 数组把跨 Loop 终点的 callback 切成连续时间段；循环跨界会更新 chase generation。`AudioRenderGraph` 已在一个设备 callback 内逐段渲染；`MidiEventPlan` 在向后回绕时发送上一段仍在发声的 note-off，再 chase 新位置的 controller、pitch bend 与 held note，事件偏移保持为 callback 相对位置。一个 callback 内多次回绕、精确落在 callback 边界、MIDI 输出缓冲不足和 PCM refill 预检均有回归。

MIDI schedule 专项 19/19、render graph 专项 37/37、media 全套 39/39 和 callback-thread realtime allocation probe 通过；Stable engine/media all-target strict Clippy、格式和 diff 检查通过。looped graph callback 已加入无分配探针。媒体层的严格受限 feeder 支持两种精确映射：bounded loop-source section 的帧数等于 transport loop 长度且 item offset 为零；或 loop-source item 没有显式 source section、非负 source offset 起始的 trimmed source 段长度等于 Loop 长度。两种情况都要求立体声、item 完整时间范围等于 transport loop、解码率等于输出率。应用播放构建层把项目 tick 范围通过 tempo map 转成采样范围，并将 feeder 和实时 Transport 接起来。其它 feeder 若需要重新读取已消费的 loop-start PCM，图仍在 callback 预检阶段返回 `AudioItemSeekRequiresRefill`，且不推进 transport、不消费 PCM、不改输出。异步 CLAP helper 的 ahead-of-time MIDI/音频量子仍按线性 sample clock 规划；发生回绕时 callback 在修改状态前返回 `LoopedIsolatedInstrumentUnsupported`。

Ruler 现在按 Default 7 底栏绘制窄括线与两端手柄；拖动任一端点时显示预览，释放时一次性提交。普通拖动底栏建立按下位置的零长度点；Shift+拖 bracket 主体会显示保留区间长度的预览，按当前 Snap 网格移动起点并一次提交，链接时同步 Time Selection。空白 lane 点击在释放时定位编辑光标，单击不创建范围。Time Selection 与 Loop points 现以相对工程采样原点的秒数随工程状态原子保存，重载后按该工程的 tempo map 还原到 timeline tick；时间范围编辑会标记工程未保存。40621 的链接偏好独立保存在平台全局配置目录下的 `loop-time-preferences.json`，默认开启，变更经 500 ms 防抖后原子写入，并在主窗口关闭前刷新；它不会标记工程为未保存。Action List 的 State 列也会按当前链接值显示 `on`/`off`。实窗截图[AAADAW Loop/Time Selection](fixtures/loop-time-selection-aaadaw.png)在未链接的 `[1,2]` Time Selection 与 `[3,4]` Loop points 下显示该底栏；它与原厂截图的窗口尺寸/缩放不同，不作为完整窗口几何验收。

Repeat 现在有应用侧入口：底部 Transport `Repeat` 按钮与 Action List `Toggle repeat`（默认 `R`）共用状态；播放中切换 Repeat 或编辑 Loop points 会准备替换播放图，tick 端点通过工程 tempo map 转成项目采样。Loop 可达时，mono 或 stereo PCM item 可以完整覆盖 Loop，也可以只与 Loop 部分相交；feeder 只读取 item 与 Loop 交集对应的源帧，并以该交集的项目采样标签循环。source rate 可不同于工程 rate，但交集起点及持续时间必须映射到整数源帧；worker 会预热循环重采样器的环绕相位，非整帧映射在启动图之前拒绝。Loop source 开启的 bounded section 仍必须恰好映射整个 Loop、offset 为零；普通 trimmed item 不要求 item 自己打开 Loop source。mono 按居中声像转换到 stereo render graph。即使起播位置已越过某个 item、但仍在 Loop 内，也会为下一轮准备该交集；起播位置越过 Loop 末端时则改用普通 seek feeder，让跨过 Loop 的 item 继续线性播放。若游标仍在 Loop 前且普通 trimmed item 已在 Loop 前开始，同采样率 feeder 会从当前游标（或更晚的 item 起点）线性输出至 Loop 交集，再重复该交集。异采样率的预循环前缀目前会以 `UnsupportedLoopResamplingPrefix` 在 feeder startup 阶段拒绝：短循环的 sinc 左侧历史需要跨多个周期稳定，当前 worker 尚不能为此前缀提供周期一致的滤波历史。isolated helper 仍在 callback 前拒绝，不会临时跳过或错误混音。该入口尚无 Linux REAPER 与 AAADAW 同场播放/截图对照。

REAPER 7.82 / Default 7 的隔离 ReaScript 探针在 Dummy Audio 下开启 Repeat、设 Loop 为 `[1,2]` 秒后，分别从 0、1.5、3 秒启动；约 0.325 秒后播放头在 0.325、1.813、3.348 秒。播放从 Loop 后的 3 秒启动时，原厂保留该位置并线性推进，没有在启动时跳回 Loop 起点。数值与脚本记录见[原厂 TSV](fixtures/loop-repeat-start-native.tsv)和[探针](../../../scripts/reaper_parity/probe-loop-repeat-start.lua)。AAADAW 的 MIDI-only 与音频 app-library 回归均从 Loop 后启动，确认 transport 线性推进；音频用跨过 Loop 末端的立体声 item 逐帧检查连续源数据。

这仍不构成完整 loop 功能：40632/40633 的停止状态已按原厂探针对齐，播放期间的导航行为尚未实测；原厂空白 lane 拖动只建立零长度点，尚未找到在该 lane 一次创建非零范围的手势；Ctrl/Alt/Super、拖动中更换修饰键、端点及空白点创建的 Snap 开关语义与整段移动边界仍待核验；当前只证明 Shift 整段移动的 Snap 行为，空白点按原始鼠标按下位置实现。非整源帧边界的采样率转换、异采样率预循环前缀的周期历史处理和 isolated helper 仍未接入循环 callback；Repeat 的偏好持久化、tempo/timebase 边界及完整 REAPER 原厂窗口视觉对照未完成。
