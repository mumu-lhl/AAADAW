# MIDI Set → Contents across a stepped tempo change

Linux REAPER `7.82/linux-x86_64` with `Default_7.0.ReaperThemeZip` was opened in a fresh unsaved project. The probe added a 60 BPM tempo point at 4.000 seconds to the default 120 BPM project, then created a selected loop-source MIDI item from 3.900 to 8.900 seconds. Its source is 5.1 quarter notes (4,896 PPQ at 960 PPQ), and it contains two notes.

In the real `Nudge/Set Items` dialog (528×121), Mode was `Set`, Target was `contents`, the absolute target was 4.150 seconds, and Snap was off. Apply kept the item at 3.900 seconds with its five-second length, loop flag, selection, and note PPQ unchanged. REAPER recorded `D_STARTOFFS=2.300` seconds and source phase 4,416 PPQ; the source loop endpoint read 9,312 PPQ. The project state-change count advanced once, from 2 to 3. The [native TSV](fixtures/item-nudge-midi-variable-tempo-set-native.tsv) records the source and item state, while the [before](fixtures/item-nudge-midi-variable-tempo-set-native-before.png) and [after](fixtures/item-nudge-midi-variable-tempo-set-native-after.png) captures show the configured action and its applied source start.

AAADAW's Set → Contents path produces the same wrapped phase using the Tempo Map's backward source-time mapping. The focused App regression checks the measured PPQ phase and source offset, unchanged item bounds/events/selection, and single-step Undo/Redo. It does not close `ITEM-NUDGE-SET-001`: tempo ramps, other snapping units, bounded Audio, other targets, and broader native Undo parity remain open.

The [ReaScript probe](../../scripts/reaper_parity/probe-item-nudge-midi-variable-tempo-set.lua) reproduces the tempo map and MIDI item. It opens the native Nudge/Set dialog; set Mode/Target/value in the visible window, apply once, then write `snapshot` and `done` to the command file in `AAADAW_REAPER_PROBE_DIR` to record before/after state.
