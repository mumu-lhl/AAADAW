# MIDI Editor Quantize Events dialog

Linux REAPER 7.82 / Default 7 action 40009 opens `Quantize Events`. Its captured defaults are `Settings: Use grid`, `Quantize: Selected notes`, operation `Position`, and Strength `100%`; `Bypass` is unchecked and `Fix overlaps` is checked. The scope menu offers All notes, Selected notes, All events, and Selected events in that order. The operation menu offers Position, Position and note end, Position and note length, Note end only, and Note length only. The native dialog and both option menus are captured in the [fixture manifest](fixtures/midi-quantize-dialog-ui.tsv).

AAADAW adds `Quantize…` to the desktop MIDI Editor toolbar. Its modal uses the current MIDI Editor grid and supports All notes, Selected notes, All events, or Selected events in the native menu order for notes, CC, Pitch Bend, Program Change, Poly Aftertouch, Channel Pressure, and opaque SysEx/Meta events; all five native note operations (Position, Position and note end, Position and note length, Note end only, and Note length only); 0–100% strength; Fix overlaps (checked by default); and Bypass. The MIDI Editor selects CC, Pitch Bend, Program Change, Poly Aftertouch, Channel Pressure, and opaque SysEx/Meta rows by clicking; Ctrl/Command-click toggles additive selection. Fix overlaps trims a quantized note to the next note start with the same channel and pitch, and can also shorten an unselected earlier note that overlaps the quantized note. Bypass is off by default; when enabled, Commit makes no edit and keeps the dialog open, while OK makes no edit and closes it. Cancel and Escape discard pending dialog settings while keeping any earlier committed edit. Notes in the all-notes scope include notes hidden by the editor channel filter. Direct `Q pos` and `Q pos+end` toolbar actions remain available.

The operation math was checked against REAPER 7.82 at 100% on a 1/32 grid (120 PPQ ticks): Position moves starts and preserves lengths; Position and note end independently snaps both endpoints; Position and note length snaps starts and durations; Note end only preserves starts and snaps ends; Note length only preserves starts and snaps durations. A positive-strength note-length quantize keeps at least one grid interval when a very short note would otherwise round to zero. A distinguishing `100–280` note becomes `120–360` under Position and note length, while Note end only yields `100–240`; the unselected `550–670` note is unchanged. The exact event readbacks are in the [native operation probe](fixtures/midi-quantize-operations-native.tsv).

REAPER's 50% strength result was also measured on the 1/32 grid. Selected starts `170`, `350`, and `900` become `145`, `355`, and `930`; the `550` unselected start remains unchanged, and all durations are preserved. This matches AAADAW's midpoint interpolation. The [native result](fixtures/midi-quantize-strength-native.tsv) and [50% dialog capture](fixtures/midi-quantize-strength-50-reaper-native.png) record the comparison.

The native All events scope was measured with selected and unselected notes, CC, and Pitch Bend events. Position quantize moved every measured event to the grid while preserving note lengths, event values, channels, and selection state. AAADAW applies the same operation across those three event types as a single undoable transaction; the [native event readback](fixtures/midi-quantize-all-events-native.tsv) records the exact ticks. A second native probe placed two CC1 events and two Pitch Bend events close enough to collide after quantizing. REAPER retained the same-channel CC event with the later original tick and its value, and did the same for same-channel Pitch Bend events; AAADAW now produces the same merged result, and one Undo restores every original event. The exact readback is in the [collision fixture](fixtures/midi-quantize-all-events-collisions-native.tsv). AAADAW also applies All events to Program Change, Poly Aftertouch, Channel Pressure, SysEx, and Meta events. Automated regressions verify position changes and single-step Undo/Redo; opaque payload bytes and source order are retained. Native matching readbacks for these additional event types and opaque-event collision behavior have not been collected.

Selected events was measured with one selected note, one selected CC, and one selected Pitch Bend alongside unselected events. On a straight 1/32 grid, selected note `170–260` became `120–210`, while unselected notes stayed at `350–430` and `550–670`; selected CC1 at `475` moved to `480`, and selected Pitch Bend at `835` moved to `840`. In deliberate collisions with unselected CC1 at `480` and Pitch Bend at `840`, REAPER kept the selected event and removed the unselected one, even though the unselected event had the later original tick. Selection flags remained set. AAADAW uses that selected-event priority while retaining latest-original-event priority among All events collisions. The scope list follows the native order, and a live Xvfb click on the final menu item keeps the dialog open with Selected events selected. Applying the scope to an off-grid CC1 point visibly moves only that selected point onto the grid and preserves its selected highlight. The [native readback and dialog capture](fixtures/midi-quantize-selected-events-native.tsv), [reproducible probe](../../../scripts/reaper_parity/probe-midi-quantize-dialog-selected-events.lua), [AAADAW scope dialog](fixtures/midi-quantize-selected-events-aaadaw-dialog.png), [selected CC lane](fixtures/midi-quantize-selected-events-aaadaw-midi-editor.png), and [applied Selected events result](fixtures/midi-quantize-selected-events-aaadaw-applied.png) record the behavior. AAADAW also quantizes selected Program Change, Poly Aftertouch, Channel Pressure, SysEx, and Meta events, retains opaque payload bytes and order, and remaps selected opaque rows across sorting and Undo/Redo; automated app history coverage verifies these paths. Native results and collision behavior for the additional modeled and opaque types remain unmeasured.

REAPER was also probed with Bypass checked, All events selected, and Position at 100%. OK closed the dialog without changing selected/unselected notes, CC, or Pitch Bend values or ticks. The [native state readback](fixtures/midi-quantize-bypass-native.tsv), [checked Bypass capture](fixtures/midi-quantize-bypass-checked-reaper-native.png), and AAADAW [checked Bypass capture](fixtures/midi-quantize-dialog-bypass-aaadaw.png) record this behavior. The App regression verifies that Commit leaves the dialog open, OK closes it, and neither operation changes the project nor records an undo entry.

Fix overlaps was measured with three same-channel, same-pitch notes and Position and note length at 100%. After the MIDI editor loaded, the pre-quantize notes read back as `100–300`, `180–300`, and `330–350`. With the native default checked, the quantized output was `120–240`, `240–360`, and `360–480`; with the checkbox off, the first note remained `120–360` and overlapped the second note at `240–360`. A separate two-note Selected notes probe with only the second note selected confirmed that checked Fix overlaps shortens the unselected first note from `100–300` to `100–240`, while the selected note becomes `240–360`. With Fix overlaps off, the unselected first note stays `100–300` and the selected note moves to `240–300`, retaining its original end. Core and App now match that measured two-note behavior. Exact REAPER readbacks and checked/unchecked captures are recorded in the [Fix overlaps fixture](fixtures/midi-quantize-fix-overlaps-native.tsv). Regressions also cover All notes behavior, minimum note length, and Undo/Redo.

A longer Selected notes probe with Fix overlaps off measured a five-note same-pitch chain for Position and note length. The selected note moves from `180–300` to `240–300`; REAPER also moves its selected raw note-off from tick 300 to 360, then reports the next unselected same-key note as `330–360`. AAADAW now mirrors that measured note-table result for both the Position and Position and note length operations when the selected note overlaps an unselected predecessor and its moved end crosses the next unselected same-key note. Core and App regressions cover the five-note case and Undo; the [native event fixture](fixtures/midi-quantize-selected-overlap-chain-native.tsv), [reproducible probe](../../../scripts/reaper_parity/probe-midi-quantize-selected-overlap-chain.lua), [native dialog capture](fixtures/midi-quantize-selected-overlap-chain-reaper-native-dialog.png), and [applied MIDI Editor capture](fixtures/midi-quantize-selected-overlap-chain-reaper-native-applied.png) document both the note-table and raw-event readbacks. The fixture notes that REAPER already reports one overlapping note's end differently from its raw event stream before quantizing. The [five-note AAADAW project](fixtures/midi-quantize-selected-overlap-chain-aaadaw.aaadaw), current Cranelift [MIDI Editor capture](fixtures/midi-quantize-selected-overlap-chain-aaadaw-editor.png), and [configured Quantize Events dialog](fixtures/midi-quantize-selected-overlap-chain-aaadaw-dialog.png) record the live desktop check; the App regression applies and undoes the operation.

Quantize Events also follows the active MIDI Editor Swing grid. On REAPER 7.82 with a 1/32 grid, 50% swing, and 960 PPQ per quarter note, odd grid points move 30 ticks later: selected starts `170` and `350` quantize to `150` and `390`, while an unselected note at `550` stays put in Selected notes scope. The exact midpoint at tick `75` resolves to the later point `150`. Position and note length uses those swung points for note starts but keeps note lengths on the straight 120-tick grid; Position and note end snaps both endpoints to swing points. All events also applies the swung grid to unselected notes, CC, and Pitch Bend, and same-tick CC/Pitch Bend collisions retain the event with the latest original tick. The [native readback fixture](fixtures/midi-quantize-swing-native.tsv), [All events dialog capture](fixtures/midi-quantize-swing-reaper-native.png), and [reproducible REAPER probe](../../../scripts/reaper_parity/probe-midi-quantize-dialog-swing.lua) record these results.

App regressions verify defaults, native-matched 50% strength interpolation, all four implemented scopes, Bypass, note-length-only selection, both selected-scope and all-event collision rules, Commit, Cancel/Escape, and one-step Undo/Redo for each Core operation.

This remains a partial implementation. Native conformance for Program Change, Poly Aftertouch, Channel Pressure, SysEx, and Meta quantization is not yet measured; opaque-event destination collisions are also unprobed. Multiple selected notes or more complex mixed-selection same-key overlap chains with Fix overlaps off, and remembered dialog settings also remain open. The single selected-note neighbor case above is implemented, but these broader gaps remain in progress in the parity matrix.
