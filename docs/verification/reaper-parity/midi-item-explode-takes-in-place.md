# Explode MIDI takes in place

Linux REAPER `7.82/linux-x86_64` with the Default 7 theme was probed with Main action 40642, `Take: Explode takes of items in place`. The selected two-second MIDI item had Take A active/inactive ordering `A, B`, with note 60 in A and notes 60 and 64 in B. REAPER replaced it with two same-track, same-position, same-length MIDI items ordered A then B; each has one active take at index 0, keeps its name and MIDI data, and the exploded items are unselected. One Undo restores the original selected item, both takes, and active index 1; Redo recreates the two unselected items.

The [native ReaScript probe](../../../scripts/reaper_parity/probe-midi-explode-takes-in-place.lua) records all four states and saves their RPP projects. The [TSV](fixtures/midi-explode-takes-in-place-native.tsv), [after RPP](fixtures/midi-explode-takes-in-place-after.rpp), and [real REAPER after screenshot](fixtures/midi-explode-takes-in-place-native-after.png) are archived here; before/Undo RPPs match, as do after/Redo RPPs.

AAADAW routes action 40642 through the shared Audio/MIDI command. The app regression `exploding_mixed_audio_and_midi_takes_is_one_undo_step` now uses named MIDI takes with native-matching note contents alongside multi-take Audio, checks exploded MIDI names and pitches, verifies one project history step and cleared selection, and compares complete snapshots through Undo/Redo. The Core regression separately checks MIDI take contents, bounds, and one-step project history. Stable desktop tests pass **882/882**, and strict AAADAW Clippy passes.
