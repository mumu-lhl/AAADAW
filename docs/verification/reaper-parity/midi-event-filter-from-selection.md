# MIDI Event Filter: Set Filter from Selection

Reference: Linux REAPER 7.82, Default 7 theme. The native probe starts with three selected Notes on channels 2–4, one unselected Note on channel 5, and an existing Note/channel-5 filter.

Clicking `Set filter from selection` replaces the channel mask with channels 2–4 and populates Note, Velocity, Position in measure, and Length criteria from the selected Notes. The measured ranges are pitch C4–G4, velocity 91–93, measure position 0–0.25026042, and length 1/16–1/16. The MIDI Editor channel changes to Multichannel and Draw events on channel resets to Channel 1. Show-only, Invert, and Solo remain off, and Repeat every remains unchecked. The event data and the three selected Notes remain unchanged. Native screenshots and before/after RPP readbacks are listed in the [fixture manifest](fixtures/midi-event-filter-from-selection-native.tsv).

This probe establishes behavior for a homogeneous Note selection only. Mixed event types and selected CC, Pitch Bend, Program Change, Poly Aftertouch, Channel Pressure, Meta, or SysEx events have not been probed. AAADAW derives the selected-Note channel mask, event type, inclusive pitch and velocity ranges, position-in-measure range, and note-length range. Its [current-build Xvfb captures](fixtures/midi-event-filter-from-selection-aaadaw.tsv) confirm that the measured selection produces channels 2–4, C4–G4, velocity 91–93, position 0–0.25026042, and length 1/16–1/16; preserves the three selected Notes and the Show-only state; selects Multichannel; and resets draw channel to Channel 1. A further capture confirms Show-only displays only those three Note rows. Repeat every, Parameter, Value, and Solo filter criteria remain unimplemented. Mixed event types and all non-Note selections remain unimplemented and unprobed, so the Event List acceptance remains open.
