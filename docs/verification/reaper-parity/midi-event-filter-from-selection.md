# MIDI Event Filter: Set Filter from Selection

Reference: Linux REAPER 7.82, Default 7 theme. The native probe starts with three selected Notes on channels 2–4, one unselected Note on channel 5, and an existing Note/channel-5 filter.

Clicking `Set filter from selection` replaces the channel mask with channels 2–4 and populates Note, Velocity, Position in measure, and Length criteria from the selected Notes. The measured ranges are pitch C4–G4, velocity 91–93, measure position 0–0.25026042, and length 1/16–1/16. The MIDI Editor channel changes to Multichannel and Draw events on channel resets to Channel 1. Show-only, Invert, and Solo remain off, and Repeat every remains unchecked. The event data and the three selected Notes remain unchanged. Native screenshots and before/after RPP readbacks are listed in the [fixture manifest](fixtures/midi-event-filter-from-selection-native.tsv).

The native probe covers homogeneous Note selection. A separate CC probe selects CC7 value 64 on channel 2 at tick 480 and CC7 value 100 on channel 3 at tick 960, with an unselected CC10 and CC7 value 127 as controls. `Set filter from selection` sets the channel mask to channels 2–3, Event type to Control Change, Control to `07 Volume MSB`, Value to 64–100, and Position in measure to 1/8–0.25026042; Repeat every is `measure`. The MIDI Editor channel becomes Multichannel and Draw events on channel stays Channel 1. Show-only, Invert, and Solo remain off; the Event List filter itself becomes active. The selected CCs and MIDI source data remain unchanged. The [CC fixture manifest](fixtures/midi-event-filter-from-cc-native.tsv) records the selected-bit readback, both RPP states, and screenshots.

AAADAW derives channel, event type, controller, inclusive Value, and Position criteria from homogeneous selected CCs; it preserves the selected CCs, Show-only/Invert/Solo state, and project data, and resets Draw events on channel to Channel 1. The [homogeneous CC fixture manifest](fixtures/midi-event-filter-from-cc-aaadaw.tsv) records a real-window capture and regression. The existing [Note-selection captures](fixtures/midi-event-filter-from-selection-aaadaw.tsv) verify pitch, velocity, Position, and note Length derivation. A mixed-parameter CC selection disables Control and displays `<all>`, while deriving the selected events' inclusive Value and Position ranges. The [current-build mixed-parameter fixture manifest](fixtures/midi-event-filter-from-mixed-cc-aaadaw.tsv) records that behavior.

A mixed-parameter probe selects CC7 value 64 on channel 2 at tick 480 and CC10 value 100 on channel 3 at tick 960. REAPER disables Control and displays `<all>`, while retaining Value 64–100 and Position 0.125–0.25026042. The Event List funnel turns on and shows four rows that pass channel, type, Value, and Position, including unselected CC1 and CC10 events; Show-only remains unchecked. The before/after RPPs and [mixed-parameter fixture manifest](fixtures/midi-event-filter-from-mixed-cc-native.tsv) confirm MIDI source data and event selection bits are unchanged.

AAADAW supports both homogeneous and mixed-parameter CC selections. It disables Control for the latter, keeps the inclusive Value and Position ranges, and activates a separate Event List Filter toggle while leaving Show-only off. The [mixed-parameter AAADAW manifest](fixtures/midi-event-filter-from-mixed-cc-aaadaw.tsv) contains current-build screenshots of the dialog, the four matching rows with the two selected rows preserved, and all seven rows after turning the Event List filter off. Mixed event types and selected Pitch Bend, Program Change, Poly Aftertouch, Channel Pressure, Meta, and SysEx remain open, so Event List acceptance stays `in_progress`.
