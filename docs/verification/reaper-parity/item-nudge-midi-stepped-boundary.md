# MIDI Contents Nudge at a stepped Tempo Point

This probe isolates a MIDI loop item whose start lies exactly on a stepped tempo marker. In Linux REAPER `7.82/linux-x86_64` with the Default 7 theme, the project starts at 120 BPM and changes to 60 BPM at 2.000000 seconds (PPQ 3840). REAPER's tempo-marker API readback confirms the two points at 0 and 2 seconds. The five-second loop-source item spans 2.000–7.000 seconds. The real Nudge/Set Items window was set to Target `contents`, 250 milliseconds, with Snap off.

Action 41249 (Nudge right) changes `D_STARTOFFS` from 0 to 2.250000 seconds, and `MIDI_GetPPQPosFromProjTime` reports source phase 4320 PPQ in a 4800 PPQ loop. Action 41250 (Nudge left) advances the offset to 2.500000 seconds and reaches the 4800 PPQ loop endpoint, equivalent to phase 0. Item position, length, loop flag, notes, and selection remain unchanged. The direct actions do not increment the project state-change counter. The native values, actual dialog screenshots, and setup are in the [fixture TSV](fixtures/item-nudge-midi-stepped-boundary-native.tsv); the [ReaScript probe](../../../scripts/reaper_parity/probe-item-nudge-midi-stepped-boundary.lua) waits for right, left, or done commands.

AAADAW now converts source phase through the project Tempo Map for both stepped points and a separately measured linear ramp. The stepped-boundary App regression matches 4320 PPQ and returns to phase 0 on the left action. In the ramp case, the native phase is 4537.985 PPQ while AAADAW's integer model produces 4531 PPQ from a 4974-tick source loop. The 6.985 PPQ difference remains an open source-loop/timebase precision gap; this does not establish full Nudge parity. Other curve types, Nudge units, Set mode, multi-item anchor behavior, and broader Undo semantics also remain open.
