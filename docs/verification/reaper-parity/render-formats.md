# Linux REAPER 7.82 Render WAV formats

Reference: Linux REAPER `7.82/linux-x86_64`, Default 7 theme, isolated factory configuration. The [probe script](../../../scripts/reaper_parity/probe-render-formats-ui.lua) opens the native Render to File dialog. Its standard source is a 48 kHz stereo PCM24 file with one second of constant L=0.125/R=0.375 on each of two tracks; the Master mix renders L=0.25/R=0.75. The [WAV bit-depth menu](images/render-wav-bit-depth-native.png) lists 8/16/24/32-bit PCM, 32/64-bit floating point, 4-bit IMA ADPCM, 2-bit cADPCM, and 8-bit u-Law. The [u-Law dialog](images/render-wav-ulaw-native.png), [IMA ADPCM dialog](images/render-wav-ima-native.png), and [cADPCM dialog](images/render-wav-cadpcm-native.png) record the selected encodings. The shared [format-vector generator](../../../scripts/reaper_parity/probe-render-format-vectors.py) creates sixteen 3,000-frame level blocks in a one-second stereo source.

AAADAW's Render format picker exports six uncompressed linear formats—PCM 8/16/24/32-bit and IEEE float 32/64-bit—plus 4-bit IMA ADPCM, 2-bit cADPCM, and 8-bit G.711 u-Law. The queue freezes the selected format with the other render settings. Linear integer PCM uses signed little-endian samples except for the required unsigned 8-bit representation; optional TPDF dither is scoped to these linear PCM formats. u-Law uses the native WAVE format tag 7, companding table, and stereo/mono channel mapping; odd-length mono data receives the required RIFF pad byte. IMA ADPCM uses native tag 17 and 2041-frame blocks. cADPCM uses native tag `0xAC0C`, 4081-frame blocks, two-bit low-first packed codes, and the native 1024-byte-per-channel block layout; the media layer decodes both AAADAW output and native REAPER BWF files and trims padded frames to the `fact` count. Both ADPCM formats stream complete blocks and publish only after completion. IEEE float formats preserve samples above full scale and ignore integer dither. Float64 stores the f32 samples produced by the current render graph after promotion to f64, so the container is 64-bit IEEE float but the engine's processing precision remains f32. Writers use private sibling files; cancellation removes partial files, and publication never replaces a destination that appeared during rendering.

Unit tests verify bit depth and format tags, unsigned PCM8 values, PCM32 values, float64 headroom, G.711 u-Law vectors, IMA ADPCM block predictors and decoded level anchors, cADPCM block layout/predictors/native level anchors and at least 99% payload-byte agreement with the checked-in REAPER vector, Mono/Stereo channel mapping, dither, RIFF limits, cancellation, and no-clobber publication for every offered format. The media decoder also reads the native BWF/cADPCM fixture and checks its 48,000-frame duration and level anchors. An offline graph integration test renders all nine formats from the same project and decodes each result.

The cADPCM writer's block predictors and decoded anchors match the native vector, and at least 99% of its payload bytes match; remaining mismatches cluster around quantizer transition boundaries, so bit-exact cADPCM encoding is still open. The IMA bitstream likewise uses native headers, block predictors, and decoded level anchors but differs at some lossy nibble transitions; exact IMA encoder and dither parity remain open. Native u-Law dither, noise-shaping modes, complete BWF metadata generation, exact Render UI state persistence, large-file RF64 behavior, and full format-menu equivalence also remain open; this slice does not close `RENDER-FORMATS-001` or `UI-028`.
