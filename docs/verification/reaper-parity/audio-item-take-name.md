# Audio Item Take name

The audio Item Properties control follows REAPER's **Take name** field. REAPER's media-item label and the `$item` filename wildcard use the active take name; the native [Item Properties capture](images/reaper-item-properties-volume.png) shows that field in the Take properties group. AAADAW now stores one editable take-name value per audio item. An empty value keeps the source label on the timeline and the native `item_NN` fallback in filename patterns.

The native wildcard probe ran in Linux REAPER `7.82/linux-x86_64` with the Default 7 theme and an isolated profile. It created three one-second media items whose active take names were all `Hit`, selected the first and third, left the middle item unselected, then set the Render source to **Selected media items** and the pattern to `$item-$namenumber`. The preview named the first output `Hit-01.wav` and reported two files. The completed render listed `Hit-01.wav` and `Hit-02.wav`. This shows that `$namenumber` counts matching names in the selected render batch: the unselected matching item does not consume an ordinal. The native preview and finished dialog, source, output WAVs, and hashes are recorded in the [native fixture](fixtures/render-item-take-name-native.tsv). The separate [item-number fixture](fixtures/render-wildcards-itemnumber-native.tsv) confirms `$itemnumber` continues to use the item's project order.

The same REAPER project also tested `$item-$region-$namenumber`. When both name wildcards are present, `$namenumber` follows the Region context: the two selected items render as `Hit-Region 1-01.wav` and `Hit-Region 3-01.wav`, while the matching Item names would have produced 01 and 02. The [cross-context preview](images/render-item-region-namenumber-preview-native.png) and [finished render](images/render-item-region-namenumber-finished-native.png) record this precedence. AAADAW keeps Region-name numbering ahead of Item-name numbering and tests the same result.

AAADAW applies the name as an undoable Core action, includes it in project snapshots, and persists it with storage schema 54. The Properties window now labels the field **Take name**; its actual 526×500 X11 capture is [here](fixtures/audio-item-properties-take-name-aaadaw.png). A second [timeline capture](fixtures/audio-item-take-name-timeline-aaadaw.png) shows `Kick close` on the audio Item with its waveform loaded. Both screenshots were captured from Build ID `f70e20801196e37478f1496753c4c0431a166fc9` (binary SHA-256 `d5582b892b68e8ef815f4c570898e15f4eba6ade26b522f8465451c6c87f5359`). Core tests cover undo/redo, snapshots, empty values, and the length limit; storage tests cover round-trip persistence and schema 53 migration; App tests cover Apply and clearing the name. The render resolver regression checks the two selected `Hit` outputs as `Hit-01-01.wav` and `Hit-02-03.wav`, separating selected-batch `$namenumber` from project-order `$itemnumber`.

This closes only the audio active-take-name slice. Audio items still model a single active take, and the Media Item Properties window does not yet match REAPER's full set of item timebase, take selection, playback-rate/pitch, channel mode, envelopes, stretch, source, and batch-edit controls. AAADAW now renders selected MIDI items and resolves their `$item`/`$itemnumber`/`$namenumber` context; native MIDI instrument routing and output comparison remain open; `ITEM-PROPERTIES-001` and `RENDER-WILDCARDS-001` stay `in_progress`.
