# MIDI Editor channel selection and filtering

This slice implements channel selection and filtering for the Piano Roll and its CC/Pitch Bend lanes, following behavior measured in Linux REAPER 7.82 with the Default 7 theme. The native and AAADAW event inventories, screenshots, and source-generator hash are indexed in the [fixture manifest](fixtures/midi-channel-editor-ui.tsv).

REAPER offers `All channels`, `Channel 1` through `Channel 16`, and `Multichannel`. The `Filter Events` window independently controls the checked channel set, “Show only events that pass filter”, and “Draw events on channel”. The filter window also offers eight event types: `<all events>`, Note, Poly Aftertouch, Control Change (CC), Program Change (PC), Channel Pressure, Pitch, and Sysex/Meta. With all channels checked and show-only enabled, the native probe showed four notes for Note, three CC20 points for Control Change, and three Pitch Bend events for Pitch. `Note` plus `Invert` showed no notes and allowed Pitch Bend events through, confirming that Invert complements the combined channel-and-event-type match. Native captures of the event-type menu and each result are in the [fixture manifest](fixtures/midi-channel-editor-ui.tsv).

AAADAW provides the matching channel selector and `Filter events…` entry, including while `All channels` is selected. On first opening the panel, all 16 channel boxes are checked. Its eight event-type choices match the native list: `<all events>`, Note, Poly Aftertouch, Control Change (CC), Program Change (PC), Channel Pressure, Pitch, and Sysex/Meta. The Sysex/Meta predicate filters opaque Meta and SysEx Event List rows; these rows have no MIDI channel, so a channel-only selection still leaves them visible when this type is selected. Invert complements the combined channel/type predicate. The selected channel remains the draw target for new notes, CC points, and pitch bends. Filtering drives the Piano Roll note count, note visibility and hit testing, plus CC/Pitch Bend lane visibility and hit testing; changing the filter also clears selection of notes that become hidden. In Event List mode, channel and type filtering covers typed events and opaque Meta/SysEx rows. The [AAADAW fixture inventory](fixtures/midi-channel-event-type-aaadaw.tsv) records the visual note, CC, and Pitch lane results. The app regression `event_list_shows_text_marker_and_sysex_item_events` also verifies opaque Meta/SysEx-only filtering, channel-independent matching, and the inverted result. The [aftertouch fixture manifest](fixtures/midi-aftertouch-ui.tsv) records the native and AAADAW Event List pressure rows.

The AAADAW desktop binary was built with nightly Cranelift (Build ID `59cb80e57dc54292b25558be33a1b619ccb568d7`, SHA-256 `6b63619599cc55599121c4656973dfbf7518b6e2cad0d1b5c63a5ffe9bb6787f`) and opened in Xvfb at 1280×800. Screenshots capture the event-type menu, selected event types, the zero-note count, and the corresponding CC/Pitch lane content. The Xvfb capture also contains pale-green Arrangement note-preview pixels behind the detached MIDI Editor; those pixels are not treated as proof of Piano Roll visibility. The shared event predicate, note hit testing, CC/Pitch hit testing, and app state/count are covered by tests. Workspace Nextest passed 1439/1439 with 0 skipped under Xvfb; strict all-target AAADAW Clippy (`-D warnings`), `cargo fmt --all -- --check`, and `git diff --check` passed.

This remains a partial MIDI Editor slice. Native result behavior for the Sysex/Meta filter has not been compared row-by-row, and Solo, parameter/value/position/length criteria, track-list mode, channel-color behavior, separate floating-window controls, and full menu/toolbar/window geometry remain open. The native panel offers further selection-management actions that AAADAW has not implemented. `MIDI-CHANNEL-VIEW-001`, UI-018, UI-019, and P7 remain `in_progress`.
