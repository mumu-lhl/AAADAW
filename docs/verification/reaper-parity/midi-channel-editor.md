# MIDI Editor channel selection and filtering

This slice implements the channel view controls for the Piano Roll and its CC/Pitch Bend lanes. It follows the Linux REAPER 7.82 / Default 7 behavior observed in a disposable project containing notes, CCs, and pitch bends on channels 1–3.

In REAPER, the channel menu offers `All channels`, `Channel 1` through `Channel 16`, and `Multichannel`. Selecting one channel exposes `Filter`; when enabled, events on other channels disappear from the note grid and expression lanes. `Multichannel` opens the `Filter Events` window, where the channel set, `Show only events that pass filter`, and `Draw events on channel` are independent controls. The native menu, filtered view, filter window, project event inventory, and probe script are recorded in the [fixture manifest](fixtures/midi-channel-editor-ui.tsv), [menu capture](fixtures/midi-channel-menu.png), [filtered Channel 2 capture](fixtures/midi-channel-editor-filter-channel-2-native.png), [Filter Events capture](fixtures/midi-channel-multichannel-filter-dialog-native.png), and [event/settings TSV](fixtures/midi-channel-editor-reaper-native.tsv).

AAADAW now has the matching 18-choice channel selector and a filter toggle for a specific or multichannel selection; as in REAPER, the toggle is hidden for `All channels`. The selected channel is the target for newly drawn notes, CC points, and pitch bends. The multichannel panel provides independent channel checkboxes, an All toggle, a draw-channel selector, and a Done control. Filtering affects note counts, note drawing/hit testing/marquee selection, CC/Pitch Bend drawing, and expression-event hit testing. Changing the filter clears selection of hidden notes. The live desktop captures show All channels, the selector with two notes, the same project filtered to one source note, and the multichannel panel; a separate capture shows changing the draw target to Channel 3. Each is listed with its SHA-256 in the [fixture manifest](fixtures/midi-channel-editor-ui.tsv).

The additional native `Filter Events` probe checked channels 1 and 3–16, left Channel 2 unchecked, and kept “Show only events that pass filter” enabled. With Invert off, the editor shows the four notes on checked channels; with Invert on, the channel checks stay unchanged and only the two Channel 2 notes show. The paired REAPER captures, source-note inventory, filter state, and repeatable probe are indexed in the [fixture manifest](fixtures/midi-channel-editor-ui.tsv). AAADAW now exposes the same show-only and Invert controls in its multichannel panel. Inversion complements the selected channel mask for notes, CC, and Pitch Bend, and hidden selected notes are cleared when the state changes.

Focused regression coverage checks all/single/multiple channel matching, the 18 menu choices, hidden-note hit testing, selected-channel note insertion, and channel-filtered CC/Pitch Bend hit targets. The Linux desktop binary was rebuilt with nightly Cranelift and run under Xvfb; the screenshot workflow also captured the actual main application window. `cargo check -p aaadaw --all-targets`, the focused MIDI Editor tests, and the channel-choice tests passed. Full workspace Nextest passed 1404 tests across 74 binaries; strict workspace all-target Clippy (`-D warnings`), `cargo fmt --all -- --check`, and `git diff --check` passed. All 13 screenshot/probe hashes in the fixture manifest were verified.

This is a channel-filter slice, not full MIDI Editor parity. REAPER's Solo and parameter/value/position/length/event-type criteria, track-list mode, channel-color behavior, and complete menu/toolbar/window geometry remain open. The AAADAW panel is inline, not a separately floating native-style window. `UI-018` and `UI-019` remain in progress, and P7 remains open.
