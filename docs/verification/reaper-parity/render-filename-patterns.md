# Render filename wildcard patterns

Linux REAPER 7.82 / Default 7 places a `File name` pattern field and `Wildcards` button in the Render window. The captured selected-item case uses `$region-$item` and resolves to `bounds-ui-Region 2-item_02.wav`; the reference dialog and measured output are archived in [the native screenshot](images/render-selected-items-native.png) and [the output record](render-selected-items-native.tsv). The native Region Render Matrix fixture uses `$region-$track` and emits `Intro-Master.wav`, `Intro-Drums.wav`, `Intro-Guitar.wav`, and `Verse-Bass.wav`.

AAADAW now provides an optional filename-pattern field in its Render window and a grouped `Wildcards…` picker immediately below it. Its 17 implemented tokens are `$project`, `$title`, `$author`, `$projectnotes`, `$bpm`, `$tempo`, `$timesignature`, `$timesignum`, `$timesigdenom`, `$track`, `$tracknumber`, `$tracknameornumber`, `$region`, `$regionnumber`, `$marker`, `$markernumber`, and `$item`. These project metadata values come from the existing Project Notes model. Selecting a token appends it to the end of the pattern and closes the picker. A chosen output path supplies the directory and extension; a blank pattern retains the existing generated names. The resolver sanitizes characters unsafe in file names and rejects patterns that resolve multiple jobs to the same name before queueing. The Render job still publishes through the existing atomic batch writer.

The reproducible [capture script](../../../scripts/reaper_parity/capture-render-filename-pattern-aaadaw.sh) drives the visible Render command with Ctrl+Alt+R; set `AAADAW_OPEN_WILDCARDS=1` to capture the expanded picker, or `AAADAW_INSERT_WILDCARD=tracknumber` to click the visible token and capture the resulting field. Native UI probes accept `AAADAW_REAPER_WILDCARD_PATTERN` to replace their default pattern, and the selected-item probe can set Project Settings title, author, notes, and the fixture track name through its environment overrides and documented API fields. Native captures verify `$tracknumber-$tracknameornumber-$regionnumber-$tempo-$timesignature-$timesignum-$timesigdenom` as `01-Render fixture-02-120-4-4-4-4.wav`, `$markernumber` as `01.wav`, `$title-$author-$projectnotes` as `Wildcard Session-Render Author-Mix notes.wav`, and an empty track name with `$tracknameornumber` as `Track 01.wav`. See the [native context capture](fixtures/render-wildcards-context-native.png), [native marker capture](fixtures/render-wildcards-marker-native.png), [native metadata capture](fixtures/render-wildcards-metadata-native.png), and [unnamed-track capture](fixtures/render-wildcards-unnamed-track-native.png). Screenshot hashes, native inputs, implementation tokens, and regression results are in the [fixture manifest](fixtures/render-filename-pattern-aaadaw.tsv).

The regression resolves the native `$region-$track` matrix pattern to the same four native target names, renders those jobs through AAADAW's offline audio renderer, and compares every PCM24 sample to the matching REAPER output. A second test resolves `$region-$item` to the observed `Intro-item_01.wav` form. The context-expansion regression checks Project Notes title/author/text plus track, region, tempo, and time-signature values; an unnamed track resolves `$tracknameornumber` to the native `Track 02` form. The native unnamed-track render preview shows `Track 01.wav`. Separate cases cover `$project`, `$marker`, `$item`, `$bpm`, safe-name conversion, blank-pattern fallback, unknown literal tokens, and duplicate-name rejection. The queue test sets `$project-$track` through the Render message and checks that queued stem paths use the expanded project and track names; it also verifies duplicate names leave the queue unchanged. The picker regression covers all 17 visible tokens, appending the selected token, and closing the menu. See the manifest for current build, screenshot hashes, and validation counts.

This does not complete REAPER Wildcards parity. The picker exposes a tested subset of the native token set and appends at the pattern end; insertion at the caret or over a selection, `$projectnotes(name)` and named-note parsing, project directory variants, region/marker/item note and name expressions, folders/parent/FX, positions and timecode, recording names, output format/channels, date/time/unique IDs, computer/user values, REAPER's full ordering and escaping rules, pattern presets and cross-launch persistence, native collision prompts, and remaining source/range combinations are open. The native context captures directly verify track number/name, region number, tempo, time signature components, marker number, and project title/author/notes. `$marker` text/name expansion and many source-dependent values still need native comparisons. `RENDER-WILDCARDS-001`, `RENDER-SOURCE-001`, and `UI-028` remain `in_progress`.
