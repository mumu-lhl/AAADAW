# Render filename wildcard patterns

Linux REAPER 7.82 / Default 7 places a `File name` pattern field and `Wildcards` button in the Render window. The captured selected-item case uses `$region-$item` and resolves to `bounds-ui-Region 2-item_02.wav`; the reference dialog and measured output are archived in [the native screenshot](images/render-selected-items-native.png) and [the output record](render-selected-items-native.tsv). The native Region Render Matrix fixture uses `$region-$track` and emits `Intro-Master.wav`, `Intro-Drums.wav`, `Intro-Guitar.wav`, and `Verse-Bass.wav`.

AAADAW now provides an optional filename-pattern field in its Render window. A chosen output path supplies the directory and extension; a blank pattern retains the existing generated names. The current resolver supports `$project`, `$region`, `$marker`, `$track`, `$item`, and `$bpm`. It sanitizes characters unsafe in file names and rejects patterns that resolve multiple jobs to the same name before queueing. The Render job still publishes through the existing atomic batch writer.

The [AAADAW window capture](fixtures/render-filename-pattern-aaadaw.png) was taken from the rebuilt desktop binary (Build ID `1f92198bb6bc4e01c9c82556cd6b62946f0bf8e6`). The reproducible [capture script](../../../scripts/reaper_parity/capture-render-filename-pattern-aaadaw.sh) drives the visible Render command with Ctrl+Alt+R. Its screenshot hash, native inputs, implementation tokens, and regression results are in the [fixture manifest](fixtures/render-filename-pattern-aaadaw.tsv).

The regression resolves the native `$region-$track` matrix pattern to the same four native target names, renders those jobs through AAADAW's offline audio renderer, and compares every PCM24 sample to the matching REAPER output. A second test resolves `$region-$item` to the observed `Intro-item_01.wav` form; separate checks cover `$project`, `$marker`, `$track`, `$bpm`, safe-name conversion, blank-pattern fallback, unknown literal tokens, and duplicate-name rejection. The queue test sets `$project-$track` through the Render message and checks that the queued stem paths use the expanded project and track names; it also verifies duplicate names leave the queue unchanged. Final validation passed the 662-test App suite before the matrix test was extended, then reran the changed REAPER PCM comparison and queue-path regression (1/1 each), strict all-target App Clippy (`-D warnings`), and the stripped-debug desktop build. Formatting also passes.

This does not complete REAPER Wildcards parity. AAADAW has no Wildcards chooser or pattern-preset UI, its filename field is optional and not saved across launches, and other REAPER tokens, ordering, escaping, date/time values, track numbering, collision prompts, and the remaining source/range combinations are unverified. `$marker` and `$bpm` currently have implementation tests but no matching native render fixture. `RENDER-WILDCARDS-001`, `RENDER-SOURCE-001`, and `UI-028` remain `in_progress`.
