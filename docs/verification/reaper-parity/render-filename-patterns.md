# Render filename wildcard patterns

Linux REAPER 7.82 / Default 7 places a `File name` pattern field and `Wildcards` button in the Render window. The captured selected-item case uses `$region-$item` and resolves to `bounds-ui-Region 2-item_02.wav`; the reference dialog and measured output are archived in [the native screenshot](images/render-selected-items-native.png) and [the output record](render-selected-items-native.tsv). The native Region Render Matrix fixture uses `$region-$track` and emits `Intro-Master.wav`, `Intro-Drums.wav`, `Intro-Guitar.wav`, and `Verse-Bass.wav`.

AAADAW now provides an optional filename-pattern field in its Render window and a `Wildcards…` picker immediately below it. The picker exposes the six implemented tokens: `$project`, `$region`, `$marker`, `$track`, `$item`, and `$bpm`. Selecting one appends it to the end of the pattern and closes the picker. A chosen output path supplies the directory and extension; a blank pattern retains the existing generated names. The resolver sanitizes characters unsafe in file names and rejects patterns that resolve multiple jobs to the same name before queueing. The Render job still publishes through the existing atomic batch writer.

The [AAADAW filename-field capture](fixtures/render-filename-pattern-aaadaw.png), [expanded picker capture](fixtures/render-filename-pattern-wildcards-aaadaw.png), and [track-token insertion capture](fixtures/render-filename-pattern-wildcard-insert-aaadaw.png) were taken from the rebuilt desktop binary. The reproducible [capture script](../../../scripts/reaper_parity/capture-render-filename-pattern-aaadaw.sh) drives the visible Render command with Ctrl+Alt+R; set `AAADAW_OPEN_WILDCARDS=1` to capture the expanded picker, or `AAADAW_INSERT_WILDCARD=track` to click the visible `$track` button and capture the resulting field. Screenshot hashes, native inputs, implementation tokens, and regression results are in the [fixture manifest](fixtures/render-filename-pattern-aaadaw.tsv).

The regression resolves the native `$region-$track` matrix pattern to the same four native target names, renders those jobs through AAADAW's offline audio renderer, and compares every PCM24 sample to the matching REAPER output. A second test resolves `$region-$item` to the observed `Intro-item_01.wav` form; separate checks cover `$project`, `$marker`, `$track`, `$bpm`, safe-name conversion, blank-pattern fallback, unknown literal tokens, and duplicate-name rejection. The queue test sets `$project-$track` through the Render message and checks that the queued stem paths use the expanded project and track names; it also verifies duplicate names leave the queue unchanged. The picker regression covers all six visible tokens, appending the selected token, and closing the menu. Final validation passed all 663 App tests, strict all-target App Clippy (`-D warnings`), the stripped-debug desktop build, rustfmt, diff checks, and fixture/hash validation.

This does not complete REAPER Wildcards parity. The picker only exposes the six implemented tokens and appends at the end of the pattern; insertion at the caret or over a selection, the full REAPER token set, ordering and escaping rules, date/time values, track numbering, pattern presets and cross-launch persistence, native collision prompts, and the remaining source/range combinations are open. `$marker` and `$bpm` have implementation tests but no matching native render fixture. `RENDER-WILDCARDS-001`, `RENDER-SOURCE-001`, and `UI-028` remain `in_progress`.
