# File > Project templates

AAADAW stores Linux desktop project templates in `$XDG_CONFIG_HOME/aaadaw/ProjectTemplates` (or `~/.config/aaadaw/ProjectTemplates`). The File > Project templates cascade follows REAPER's menu structure: `Save project as template...`, `Show project template path in explorer/finder`, a separator, the disabled `Load project template:` label, then `.aaadaw` files in case-insensitive filename order. An empty folder shows the disabled `(no project templates)` row. Mobile/touch File menus keep the entries inline.

The folder command opens the platform file manager (`xdg-open` on Linux). Saving a template writes a complete AAADAW project and its managed audio assets into that folder. The file name gets an `.aaadaw` extension when needed. A new name is saved without replacing an existing entry. If the selected path already names a regular file, AAADAW opens a modal `File exists: [absolute path] / Overwrite?` prompt. OK rechecks the destination and atomically replaces it with a temporary SQLite project file; Cancel, Escape, and clicking the backdrop leave its bytes untouched. A missing, non-file, or currently open project target is refused, and a failed write leaves the original intact. The native file picker opens in the template folder. If the user navigates to another folder, AAADAW reports that the template must be saved in `ProjectTemplates` instead of silently redirecting the selected name.

Opening a template through the cascade first passes through the ordinary unsaved-project transition guard, then copies the locked source project to a private temporary working directory. AAADAW opens and edits that copy, leaves the template source untouched, and does not add the working copy to Recent projects. Escape does not discard that copy while its asynchronous project load is in flight. Project files opened directly from inside the template folder are also recognized: ordinary Save and Save new version route through Save As, and writes to the template folder are rejected. Saving directly to the source template or an active temporary copy is rejected as well; a successful Save As transfers audio assets, switches the project to the new destination, and removes the old working copy. Replacing or closing the project releases the session lock before removing its temporary directory.

The Android save command is disabled because its current SAF staging flow cannot yet atomically publish a template into the internal `ProjectTemplates` folder. Android template saving remains open; Linux is the parity target for this slice.

## Verification

`app::project_templates` tests cover sorted listing, working-copy cleanup/source preservation, extension normalization, rejecting destinations outside the template folder, canonical path classification, and direct-open template detection. App tests cover guarded opening, a valid confirmed replacement, failed-write preservation, the modal overwrite state and Escape cancellation, refusal to replace the currently open project, omitted MRU entries, routing ordinary Save through Save As, and new template files being valid and non-overwritable. The final-source Stable AAADAW desktop suite passed 716/716; strict all-target Clippy (`-D warnings`), rustfmt, and `git diff --check` passed.
