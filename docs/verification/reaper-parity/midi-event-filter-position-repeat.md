# MIDI Event Filter: Position and Repeat

Reference: Linux REAPER 7.82, Default 7 theme. The native Filter Events dialog exposes a Position in measure range and a Repeat every period. The saved native project stores the selected `1/8`–`1/8` position as `0.125`–`0.125` in `EVTFILTER`.

The native probe creates a four-measure item with 128 CC7 events spaced every 120 ticks. With Show-only enabled and Position in measure set to `1/8`–`1/8`, Repeat every `measure` shows ticks 480, 4320, 8160, and 12000. Choosing `1/2` shows eight matches, twice per measure. Choosing `1/4` shows sixteen matches, four per measure. An edge probe at Position `3/4` shows four matches with Repeat every `measure`, but no matches with Repeat every `1/4`; the selected position does not wrap to a phase inside the shorter repeat interval. The saved project, all 128 MIDI events, screenshots, counts, and ReaScript are recorded in the [native fixture manifest](fixtures/midi-event-filter-position-repeat-native.tsv).

AAADAW now uses one shared position range and repeat period for Note and Control Change filters. The same criteria drive Event List visibility, controller-lane visibility, and Set/Add/Remove selection. Repeat periods use REAPER's `1/8T`, `1/8`, `1/4T`, `1/4`, `1/2T`, `1/2`, and `measure` choices. Position bounds accept normalized decimal values from 0 to 1; the Filter Events controls still need native-style musical-value pickers. The regression exercises the four-, eight-, and sixteen-match cases for both Notes and CCs and verifies Set selection against the CC filter.

An AAADAW Cranelift desktop build was opened on the generated four-measure fixture. With Show-only enabled, Control Change / `07 Volume MSB`, position `0.125`–`0.125`, and Repeat every `1/4`, Event List reports 16 matching events at the same four-per-measure positions as REAPER. The real-window screenshot shows the active filter and first 11 rows; its 16-event count and full position sequence are also covered by the regression. The project generator, project, screenshot, binary hash, and Build ID are in the [AAADAW fixture manifest](fixtures/midi-event-filter-position-repeat-aaadaw.tsv). This is behavior evidence, not pixel-diff certification.

The native meter probe covers 4/4 at 960 PPQ. Separate native `Set filter from selection` probes confirm that homogeneous selected CC7 and Pitch Bend events derive inclusive position ranges. AAADAW now applies those Position criteria to Note, CC, and Pitch Bend rows when the Event List funnel is enabled. Pitch Bend uses the measure period and its Repeat control is disabled, matching the native dialog. Position filtering for Program Change, Aftertouch, Channel Pressure, and opaque Meta/SysEx rows remains open. Native behavior in non-4/4 meters remains unmeasured. `MIDI-EVENT-LIST-001`, UI-019, and P7 stay `in_progress`.
