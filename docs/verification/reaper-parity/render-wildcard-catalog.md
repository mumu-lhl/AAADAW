## Expansion rules observed in native help

- Capitalizing the first character of a wildcard capitalizes the first character of its substitution. Capitalizing its first two characters uppercases the substitution; a lowercase first character and uppercase second character lowercases it.
- `<X>` removes the character `X` from a substitution. `<abcdeX>` replaces each character in `abcde` with `X`; for example, `$track< >` removes spaces and `$track< _>` replaces spaces with underscores.
- A `[N]` suffix numbers repeated outputs with zero padding, as in `$filenumber[01]` or `$regionnumber[001]`. `[<N]` keeps the first N characters of a value, as in `$region[<4]`.
- If a wildcard expands to an empty value, an adjacent space, hyphen, underscore, or dot is omitted. The Render Options menu can allow `/` in substitutions and create directories; `$folders` and `$trackslashes` override that setting.
- `{lane}` on region or marker tokens limits expansion to objects on that ruler lane. Named values use `name=value` text: `$projectnotes(name)`, `$region(name)`, `$marker(name)`, `$itemnotes(name)`, and `$takemarker(name)` select matching values. A `[s]` suffix on Region and Marker values splits `name=value` entries at `s`, so a later matching key can be selected; help page 2 demonstrates `$marker(first)[;]` and `$marker(last)[;]`. Project Notes values use newline-separated entries; a native `$projectnotes(last)[;]` probe with semicolon-separated notes leaves `[;]` literal and does not resolve `last`. The help also says the same named-value rules apply to item notes.
- The Position/Length help defines clock, beats, timecode, absolute-frame, total-seconds, and split length fields. Recording tokens depend on output-file order, timeline order, item/region name collisions, or the MIDI note sequence, depending on the token.

The captured Output Format previews confirm `wav-44100-44.1-24-2` for 44.1 kHz / 24-bit / stereo, `wav-44100-44.1-24-1` for mono, and `wav-22050-22.05-2-1` for 22.05 kHz / 2-bit cADPCM / mono. Native previews also show `$bitdepth` as `16`, `4`, and `2` for PCM16, IMA ADPCM, and cADPCM respectively. ## AAADAW status

AAADAW implements 48 tokens: `$project`, `$title`, `$author`, `$projectnotes`, `$projectnotes(name)`, `$bpm`, `$tempo`, `$timesignature`, `$timesignum`, `$timesigdenom`, `$track`, `$tracknumber`, `$tracknamenumber`, `$region`, `$regionnumber`, `$regionnumber[N]`, `$regionname`, `$region(name)`, `$marker`, `$markernumber`, `$markernumber[N]`, `$markername`, `$marker(name)`, `$item`, `$itemnumber`, the 18 Position/Length entries above, and `$format`, `$samplerate`, `$sampleratek`, `$bitdepth`, and `$channels`. `$bpm` and `$tracknameornumber` are accepted compatibility forms outside the captured native menu labels; `$tracknamenumber` is the exact native menu spelling. `$regionname` and `$markername` return the matching object's name with no number fallback; native All project regions renders produce `Verse-Start.wav` and `Chorus-Next.wav`, while blank names stay empty and their adjacent separator is removed. The [native name-only fixture](fixtures/render-wildcards-region-name-native.tsv) records both results. `$region(name)` and `$marker(name)` return the value after the named `key=` in the matching object's name, with optional `[s]` splitting entries so a later matching key can be selected. The [named-value fixture](fixtures/render-wildcards-region-named-values-native.tsv) records `[|]` and unsuffixed behavior; the [second-key fixture](fixtures/render-wildcards-region-named-values-second-key-native.tsv) records native renders for a key after `[;]`. The native menu groups items hierarchically; AAADAW currently presents its flat grouped picker in a scrollable panel. Its lower rows and real token insertions are shown in the [scrolled AAADAW picker](fixtures/render-filename-pattern-wildcards-scrolled-aaadaw.png), [sample-rate](fixtures/render-filename-pattern-wildcard-sampleratek-aaadaw.png), [named project-note](fixtures/render-filename-pattern-wildcard-insert-aaadaw.png), [item-number](fixtures/render-filename-pattern-wildcard-itemnumber-aaadaw.png), [numbered-region](fixtures/render-filename-pattern-wildcard-region-number-aaadaw.png), [Region name](fixtures/render-filename-pattern-wildcard-regionname-aaadaw.png), and [Marker name](fixtures/render-filename-pattern-wildcard-markername-aaadaw.png), [Region value](fixtures/render-filename-pattern-wildcard-region-namedvalue-aaadaw.png), [Marker value](fixtures/render-filename-pattern-wildcard-markernamedvalue-aaadaw.png), and [track name or number](fixtures/render-filename-pattern-wildcard-tracknamenumber-aaadaw.png) captures.

AAADAW now applies the help-documented capitalization modes, `<X>` character removal, `<abcdeX>` character replacement, `[<N]` prefix truncation, and removal of one adjacent space, hyphen, underscore, or dot when a resolved value is empty. `$region` and `$marker` fall back to the two-digit visible object number when the matching object has an empty name; a native `All project regions` render confirms `$region-$marker` produces `01-01.wav` and `02-02.wav`, with screenshots and output hashes in [the unnamed-object fixture](fixtures/render-wildcards-empty-name-native.tsv). A second native render verifies `$regionname-$markername` produces `Verse-Start.wav` and `Chorus-Next.wav`, and blank names do not get a number fallback; see [the name-only fixture](fixtures/render-wildcards-region-name-native.tsv). For `$regionnumber[N]` and `$markernumber[N]`, `N` is parsed as a starting number and subsequent region/marker ordinals increment it while preserving the requested digit width; AAADAW regression coverage checks both expressions and the resulting filenames. Native help page 3 explicitly defines the region-number sequence, and the captured Regions/Markers menu lists both numbered forms. A fresh native Render probe set `$markernumber[005]`, selected `All project markers`, and rendered `marker-005.wav`, `marker-006.wav`, and `marker-007.wav`; the dialog and finished-render screenshots plus output hashes are recorded in [the numbered-marker fixture](fixtures/render-wildcards-markernumber-all-markers.tsv). Project-note named lookup `$projectnotes(name)` is implemented from the captured help example. The rest of the native catalog and syntax remain open: item/take-marker named-value expressions, directory and folder hierarchy, parent and FX names, marker identity and ordering, item notes and take markers, recording counters, date/time and unique IDs, user/computer values, other `[N]` render-order counters, `/` directory creation, `{lane}`, presets, `Master $Track` substitution, non-WAV formats, and per-channel `$chid` need implementation or additional source-specific REAPER comparisons. `RENDER-WILDCARDS-001` remains `in_progress`.
