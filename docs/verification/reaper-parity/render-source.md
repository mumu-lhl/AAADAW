# Linux REAPER 7.82 Render source modes

The official [REAPER 7.81 User Guide, section 21.5](https://www.reaper.fm/userguide/ReaperUserGuide781c.pdf) describes Selected tracks via master as rendering each selected track through its folder and send paths, then through Master processing, without including unrelated media from those paths. The official [ReaScript GetSetProjectInfo reference](https://www.reaper.fm/sdk/reascript/reascripthelp.html#GetSetProjectInfo) assigns `RENDER_SETTINGS=128` to Selected tracks via master; `RENDER_SETTINGS=0` is Master mix. The installed REAPER 7.82 API reference contains the same values.

The [probe script](../../../scripts/reaper_parity/probe-render-source.lua) ran in a fresh isolated 7.82 configuration and Default 7 theme. It set up two identical, centered tracks from one 48 kHz PCM24 source. With one track selected, Master mix (`RENDER_SETTINGS=0`) and Selected tracks via master (`RENDER_SETTINGS=128`) each produced one 48 kHz PCM24 stereo file with 48,000 frames. Stable samples were `[0.25, 0.75]` for the Master mix and `[0.125, 0.375]` for the selected track; `$track` produced `selected-via-master-Selected.wav`.

The same script then selected both tracks and rendered flags 128 with pattern `selected-stems-$track`. REAPER produced exactly `selected-stems-Selected.wav` and `selected-stems-Unselected.wav`. Each file was 48 kHz PCM24 stereo, 48,000 frames, 288,000 data bytes; each first frame was approximately `[0.125000015, 0.375000045]`. The Master mix control measured approximately `[0.250000030, 0.750000089]`. The run log read back flags 0/128 and selection counts 1/2. This verifies the native multi-selection file count, per-track isolation, output format and basic wildcard expansion, but does not cover duplicate/unsafe names, folder/send routing, FX behavior or other render settings.

With both tracks selected, flags 1 (`Master mix + stems`) produced `master-plus-stems-Master.wav`, `master-plus-stems-Selected.wav`, and `master-plus-stems-Unselected.wav`. All three files were 48 kHz PCM24 stereo and 48,000 frames. Their first frames were respectively approximately `[0.250000030, 0.750000089]`, `[0.125000015, 0.375000045]`, and `[0.125000015, 0.375000045]`. The flags read back as 1 before and after rendering. This confirms the Master mix plus selected-track stems behavior for this controlled case.

The same probe requested flags 2 (`stems only`), 129, and 130 with two tracks selected. REAPER accepted those values on the setter readback before rendering, but after each render `RENDER_SETTINGS` read back as 0 and only a `*-Master.wav` file was produced, with the combined Master samples. This script path therefore does not establish flags 2 or combined 128 modes; plain stems remains unimplemented pending a UI-based 7.82 probe.

AAADAW exposes `Master mix`, `Master mix + stems`, and `Selected tracks via master` in the measured order. One selected track in Selected tracks via master retains the chosen single output path. Multiple selected tracks are captured in Arrange order and rendered independently through the existing offline Master graph; the chosen filename stem becomes a prefix (`mix.wav` plus track `Bass` creates `mix-Bass.wav`). Master mix + stems adds `mix-Master.wav` alongside each selected track stem. Output collisions are rejected rather than overwritten. All outputs are first rendered in a private directory beside the targets; cancellation publishes none, and a runtime publication failure removes outputs already linked by that render. Existing files remain untouched. The per-track render snapshot soloes only its requested track; the saved project, live playback, and UI selection are not modified. Regression coverage verifies two identical media sources each produce `[0.125, 0.375]`, not the doubled Master mix, verifies the additional `[0.25, 0.75]` Master output, and covers queue snapshots, cancellation, output collisions and publish rollback.

Wildcard pattern editing and full REAPER filename rules, plain stems, pre-fader stems, region matrix, items, Razor edits, multichannel routing, folder/send FX parity and full Render window comparison remain incomplete. The multi-file picker path is currently desktop-only; Android's single-document picker disables multi-file submission. `RENDER-SOURCE-001` and `UI-028` stay `in_progress`.
