# Linux REAPER 7.82 Render source modes

Reference target: Linux REAPER `7.82/linux-x86_64`, Default 7 theme, fresh isolated configuration. The official [REAPER 7.81 User Guide, section 21.5](https://www.reaper.fm/userguide/ReaperUserGuide781c.pdf) and installed ReaScript API document Master mix, selected-track stems, Master mix plus stems, region matrix, selected media items and Razor edit areas. The API also documents `RENDER_SETTINGS=128` as selected tracks via Master; this setter mode is separate from the visible Source menu.

The [script probe](../../../scripts/reaper_parity/probe-render-source.lua) used two identical selected tracks from one 48 kHz PCM24 source with constant L=0.125/R=0.375. Through the most-recent-settings render action, Master mix produced one 48 kHz PCM24 stereo file with 48,000 frames and first samples `[0.25, 0.75]`. `RENDER_SETTINGS=128` produced one per selected track; selecting both produced `selected-stems-Selected.wav` and `selected-stems-Unselected.wav`, each with 48,000 frames and `[0.125, 0.375]`. The `RENDER_SETTINGS=1` probe produced Master plus both stems. This verifies the API modes with unity Master gain.

The initial `RENDER_SETTINGS=2` setter probe reported Master mix after rendering because setting the project field alone did not reliably synchronize the Source menu used by the render action. It was not evidence that the native stems source was unsupported. The [UI probe](../../../scripts/reaper_parity/probe-render-source-stems-ui.lua) opens the actual Render dialog in a fresh profile with two selected tracks and the Master fader at linear gain 0.5 (−6.0206 dB). Choosing `Master mix and stems` rendered `master-and-stems-Master.wav`, `...-Selected.wav`, and `...-Unselected.wav`. All were 48 kHz PCM24 stereo with 48,000 frames. Their first frames were all `[0.125, 0.375]`: the summed Master signal was halved by its fader, while each individual stem remained at the track signal level.

Choosing `Selected tracks (stems)` in that same dialog rendered two files, `native-stems-Selected.wav` and `native-stems-Unselected.wav`; each was 48 kHz PCM24 stereo, 48,000 frames, first frame `[0.125, 0.375]`. The dialog showed two files before rendering. The captured native source menus are [Selected tracks (stems)](images/render-selected-stems-native.png) and [Master mix and stems](images/render-master-and-stems-native.png). The UI probe script and screenshot document the actual source path rather than inferring it from project-field readback.

The native `Render stems pre-fader` checkbox was probed with each selected track's `D_VOL=0.5` and the same source. Unchecked, `postfader-Selected.wav` and `postfader-Unselected.wav` each contained `[0.0625, 0.1875]`; checked, `prefader-Selected.wav` and `prefader-Unselected.wav` each contained `[0.125, 0.375]`. All four files were 48 kHz PCM24 stereo with 48,000 frames. This confirms that the option bypasses the selected track volume fader for stems. The paired [post-fader](images/render-post-fader-stems-native.png) and [pre-fader](images/render-pre-fader-stems-native.png) captures show the checkbox state and two-file output preview. `RENDER_SETTINGS` bit 8192 corresponds to the checked control; the [probe script](../../../scripts/reaper_parity/probe-render-prefader-stems.lua) opens either state in the native Render dialog. Native automation and folder/send behavior remain to be compared.

AAADAW now provides a separate `Selected tracks (stems)` mode. Each track is rendered from an isolated project snapshot with its track processing and track fader, while the temporary Master gain and final Master safety clamp are bypassed. `Render stems pre-fader` additionally resets the selected track's temporary volume fader and clears its volume automation; native automation behavior is still pending comparison. `Master mix and stems` combines the normal Master output with plain stems, or pre-fader stems when enabled; selected-tracks-via-Master remains distinct and disables the checkbox. Grouped outputs still stage beside the destination, reject existing paths, publish only after all renders finish, and remove partial publication on failure. Integration tests use duplicate source tracks to assert Master mix `[0.125, 0.375]`, plain stems `[0.125, 0.375]`, via-Master stems `[0.0625, 0.1875]`, and pre-fader output independent of static fader/automation gain; they also cover WAV frame counts, cancellation, collisions and rollback.

### Selected media items

The [Linux REAPER 7.82 Render window capture](images/render-selected-items-native.png) shows Source set to `Selected media items`, the native `1 media item` count, and a one-file preview. The separate [finished-render capture](images/render-selected-items-finished-native.png) reports WAV 24-bit PCM, 48 kHz, stereo, and a 1.000-second result. The [AAADAW Render window capture](images/aaadaw-selected-items-render.png) shows the corresponding Source, selected-item count, and disabled Tail controls with an actual selected item in Arrange. The native probe used the second of three one-second items, with `$region-$item` as the filename pattern; in this fixture REAPER resolved it to `bounds-ui-Region 2-item_02.wav`. The [sample/hash fixture](render-selected-items-native.tsv) records the exact 48,000-frame result and comparison values.

The fixture source was constant 48 kHz PCM24 stereo, L=0.125/R=0.375. At the inspected sample points spanning the full second, the rendered PCM integers matched the source exactly (`[1048576, 3145728]`). This establishes direct media-source output for this plain item. A separate fresh-project probe set both the media item's `D_VOL` and its track's `D_VOL` to 0.5. REAPER rendered 48 kHz PCM24 stereo, 48,000 frames, with first samples `[262144, 786432]` (`[0.03125, 0.09375]`); the control with only item gain at 0.5 produced `[524288, 1572864]`. This confirms that both item and track gain affect selected-item output. The [native Render dialog capture](images/render-selected-items-with-item-and-track-gain.png) and [sample/hash record](render-selected-item-volume-native.tsv) preserve the setup and output.

The native Item Properties window identifies its Volume/pan control under **Take properties**. With media-item `D_VOL=0.5`, the take field showed `0.00dB` and `center`; after entering `-6.02dB`, reopening the window showed that value. The [default native dialog](images/reaper-item-properties-volume.png), [applied native dialog](images/reaper-item-properties-take-volume-applied.png), and [take-mix observation record](item-properties-take-mix-native.tsv) document this distinction. A separate REAPER selected-item render at take volume 0.5 matched AAADAW's take gain and linear-balance law for center, 25%R, hard left, and hard right. The [native setup](images/render-selected-item-take-mix-setup-native.png), [finished render](images/render-selected-item-take-mix-finished-native.png), and [sample/hash record](selected-item-take-mix-native.tsv) capture the comparison. A Master volume/pan probe confirmed both controls are bypassed for this source; see its [setup](images/render-selected-item-master-mix-setup-native.png), [finished render](images/render-selected-item-master-mix-finished-native.png), and [sample/hash record](selected-item-master-mix-native.tsv). A second probe set REAPER's stock JS Volume Adjustment Master FX to +3 dB; selected-item output remained unchanged, so that effect is bypassed too. Its [setup](images/render-selected-item-master-fx-setup-native.png), [finished render](images/render-selected-item-master-fx-finished-native.png), and [sample/hash record](selected-item-master-fx-native.tsv) preserve the result; other Master FX types remain unverified. Item/take FX and automation remain open. To reproduce these probes, run [`probe-render-selected-item-volume.lua`](../../../scripts/reaper_parity/probe-render-selected-item-volume.lua), [`probe-render-selected-item-take-mix.lua`](../../../scripts/reaper_parity/probe-render-selected-item-take-mix.lua), [`probe-render-selected-item-master-mix.lua`](../../../scripts/reaper_parity/probe-render-selected-item-master-mix.lua), and [`probe-render-selected-item-master-fx.lua`](../../../scripts/reaper_parity/probe-render-selected-item-master-fx.lua) in REAPER 7.82 with an isolated Default 7 config and `AAADAW_REAPER_PROBE_DIR`.

AAADAW accepts selected audio items, retains only each selected item in an in-memory snapshot, and renders it through the regular track graph at its original timeline position while setting Master volume/pan to unity/center. The offline regression combines selected-item D_VOL, take volume, and track volume at 0.5 each while the project Master has -6.02dB and 50%R; output contains only the selected source multiplied by the three item/take/track gains. Core/storage tests cover undo, snapshot, schema migration, and persistence; engine tests cover live take-volume and linear-balance updates. The [default AAADAW Item Properties capture](images/aaadaw-item-take-mix-properties.png) and [applied capture](images/aaadaw-item-take-mix-properties-applied.png) show `Volume/pan`, `-6.02dB`, and `25%R`; this dialog remains 526×390 and lacks most native Item/Take/Source controls. Native render comparisons confirm take gain/balance coefficients, that Master volume/pan are bypassed, and that the tested stock JS Master gain effect is bypassed. Selected MIDI items are rejected rather than silently omitted. REAPER wildcard editing and naming rules are not reproduced by the current `prefix-item_NN.wav` naming; other Master FX types, item/take FX and automation are not fully verified, and Android's single-document picker still cannot submit a multi-file render. Folder/send behavior for this source remains unverified.

Wildcard editing and complete REAPER filename rules, region matrix, Razor edit areas, multichannel routing, native pre-fader automation behavior, folder/send behavior, other Master/item/take FX comparisons, and full Render-window interaction remain incomplete. `RENDER-SOURCE-001` and `UI-028` remain `in_progress`.
