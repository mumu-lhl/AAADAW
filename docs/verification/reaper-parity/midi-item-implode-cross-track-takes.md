# Implode selected MIDI items across tracks into Takes

Linux REAPER 7.82 / Default 7 Main action 40438, **Take: Implode items across tracks into takes**, uses the selected item on the topmost selected track as the destination. This remains true when a donor starts earlier in project time. The destination keeps its position, length, existing Take order, and active Take. Donor Takes append by track order, then item order; donor items are removed and the destination alone remains selected.

The native probe used three selected tracks. The destination began at 1 second with a 2-second range and source offset 0.125 seconds. The earlier donor began at 0 seconds and contained two Takes with offsets 0.25 and 0.375 seconds; the lower donor began at 2 seconds with offset 0.5 seconds. After the action, the destination held four Takes in the order `Top target`, `Earlier donor`, `Earlier donor active`, `Lower donor`. Their offsets were 0.125, 1.25, 1.375, and −0.5 seconds. Notes, names, velocities, and the destination active Take were preserved. The negative final offset is required to keep the donor's MIDI events at their original project times when its Take is rebased to the destination position. The native state readback, RPP snapshots, and Arrange screenshot are in the [evidence manifest](fixtures/midi-implode-cross-track-aaadaw.tsv).

One Undo restores all three source items and their original selection; Redo restores the merged item and selects it. The native Undo description is `Implode items to takes`.

AAADAW exposes 40438 in the Action List and Item menu. It accepts selected MIDI items spanning at least two tracks when at least two selected items overlap. It keeps the topmost selected item as the target, orders donor Takes by track and item order, and rebases each donor's signed MIDI source offset against the target's project position. It preserves MIDI event data and active Take state, removes donor items in one transaction, and supports one-step Undo/Redo. The schema 69 migration stores signed offsets for both active and inactive Takes; loop-source mapping remains modular, while negative offsets in non-loop sources produce silence before the source begins.

The native probe is `scripts/reaper_parity/probe-midi-implode-cross-track.lua`. `crates/aaadaw/examples/generate_midi_implode_cross_track_fixture.rs` builds a matching project database, and `scripts/reaper_parity/capture-midi-implode-cross-track-aaadaw.sh` captures before/action/Undo/Redo in a 1280×800 Xvfb desktop window using isolated user directories and temporary shortcuts. The four screenshots were visually reviewed; the after view shows the single destination selected and its four-Take Inspector, and the before/Undo/Redo views record the corresponding project states. Core and Storage regressions also verify signed active/inactive Take offsets, source-event placement, persistence, and Undo/Redo.

This slice covers MIDI-only cross-track implode. The MIDI Editor and Arrange inline preview still need signed source-coordinate rendering for negative-offset Takes. Mixed Audio/MIDI selections, non-overlapping selected items, broader Take editing, recording-created Takes, Fixed Lanes, Comp Areas, and cross-project Take clipboard behavior remain open. The screenshot build disables `audio-device`; it verifies the live window and project state, not audible playback.
