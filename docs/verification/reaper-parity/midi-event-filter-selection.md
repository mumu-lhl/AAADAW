# MIDI Event Filter Selection

Reference: Linux REAPER 7.82, Default 7 theme. In the Event List, the Filter Events dialog accepts an event type and channel mask, then applies `Set selection`, `Add to selection`, or `Remove from selection` without closing the dialog.

The native probe used four Notes on channels 2, 3, 4, and 5. With Note and channel 5 as the only filter criteria, Set left only the channel 5 Note selected. Starting with channels 2–4 selected and channel 5 unselected, Add selected all four. Starting with all four selected, Remove left channels 2–4 selected and cleared channel 5. Follow-up probes disabled `Show only events that pass filter`: all four channel rows stayed visible; Set selected only channel 5; Remove from all four selected cleared only channel 5; and Add from channels 2–4 selected restored channel 5. Their RPP readbacks preserve event positions, lengths, channels, pitches, velocities, and the terminal controller; only the selected flags and saved filter-visibility option changed, apart from save timestamps. The [native fixture manifest](fixtures/midi-event-filter-selection-native.tsv) records the screenshots and readbacks.

AAADAW now exposes the same three actions in its filter dialog. Each action evaluates the channel selection, event-type criterion, and inverse setting, while the `Show only events that pass filter` checkbox controls row visibility only. Changing visibility criteria preserves selected events even when their rows become hidden; only Set/Add/Remove changes selection. Set replaces all selected event kinds, Add unions matches into the current selection, and Remove subtracts them. The synthetic End row is not selectable. Note, CC, Pitch Bend, Program Change, Poly Aftertouch, Channel Pressure, and channel-less Meta/SysEx selections use the existing Event List selection model; CC0/CC32 data is selected together through the controller selection set. Changes enter the same app-level selection history as Event List row selection and restore the Arrange inline Note selection on Undo/Redo.

The app regression exercises Set/Add/Remove with every modeled channel event type plus opaque Meta/SysEx data, confirms filter actions work with the visibility checkbox disabled, checks selection-history round trips, and verifies project MIDI data remains unchanged. Current-build Xvfb captures show Set selecting one of two Notes, Add selecting both, and Remove clearing both; see the [AAADAW capture manifest](fixtures/midi-event-filter-selection-aaadaw.tsv). Filter combinations other than Note/channel 5 remain open probes.
