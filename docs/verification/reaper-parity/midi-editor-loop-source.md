# MIDI Editor loop-source events on REAPER 7.82

Linux REAPER `7.82/linux-x86_64` with `Default_7.0.ReaperThemeZip` was probed in a fresh, unsaved project. The script created a MIDI source with a 5-second loop, put the visible 10-second item at 2 seconds, and set the take source offset to 4.75 seconds. Two source notes at 0.5 and 2.5 seconds appeared at clip-relative 0.75, 2.75, 5.75, and 7.75 seconds. The [native MIDI Editor screenshot](fixtures/midi-editor-loop-source-native.png), [captured item/source state](fixtures/midi-editor-loop-source-native.tsv), and [ReaScript probe](../../../scripts/reaper_parity/probe-midi-editor-loop-source.lua) preserve the observation.

The AAADAW screenshot was captured from a real 1000×620 MIDI Editor window on Xvfb using Build ID `108001ad22857fcc7f5ce81960203f5ec333c693` (binary SHA-256 `929def7e6e1d7835a25c89a726af78969f3f328a7d9f9f118a2fd80b69247401`). The desktop was driven through its visible controls: create a track and MIDI item, select it, add C4, extend the item from 4 to 12 quarter notes, then open Piano roll and use Fit notes. The [AAADAW screenshot](fixtures/midi-editor-loop-source-aaadaw.png) shows the shared source note repeated at the same beat in measures 1, 2, and 3 (SHA-256 `e9e28b4f7ea6309ffe983b2b43486dc0870888291c3ea91f75bd389ac2ab2c7a`). This capture uses a zero source offset; the wrapped-offset case is covered by the native screenshot and AAADAW regression tests.

AAADAW's MIDI Editor now computes visible source-event occurrences in unwrapped source coordinates, folding the item source offset through the fixed loop length and clipping results to the visible item and editor range. Each source event is capped at 4096 displayed occurrences per query to bound work on extreme clip lengths. Piano-roll drawing, selection marquee, hit testing, and drag previews use those occurrences while edits continue to target the shared source note. New notes are normalized into the loop source and shortened at the source-loop seam. CC and pitch-bend lanes draw and hit-test repeated instances and normalize edits back to the stored source tick. Core note, controller, pitch-bend, and quantize validation now uses loop-source bounds; note durations cannot cross the source-loop seam.

The loop offset regression in `midi_editor.rs::looped_source_occurrences_render_and_hit_test_after_wrapping_the_offset` checks the visible notes at unwrapped ticks 10560 and 20160 for a 9600-tick source loop offset by 9120 ticks. It also checks CC/Pitch Bend hit coordinates and normalized note insertion, including a note at the loop seam. `midi_source_loop.rs::loop_source_edits_use_source_bounds_after_the_item_offset_wraps` checks source-relative add/edit, controller/pitch-bend writes, quantization through the item offset, Undo/Redo, and rejection of a note that crosses the seam.

Validation on this build: the full `aaadaw-core` test package passed 130 tests across 39 suites; the full AAADAW desktop test binary passed 579 tests, including the wrapped-offset piano-roll and lane regressions. Core and AAADAW all-target Clippy with warnings denied passed; `cargo check --locked -p aaadaw-core -p aaadaw`, formatting, and diff checks passed. The desktop build-and-smoke helper also launched the 1280×800 main window, and the actual Piano roll window was captured separately.

This closes the loop-occurrence rendering and basic source-event editing gap for the existing piano-roll and CC/Pitch Bend lanes. The screenshot is not a full layout comparison. A user-facing loop-source toggle/source-length editor, native offset editing inside this AAADAW visual capture, complete MIDI Editor gestures/menus, and broader REAPER comparisons remain open. `ITEM-NUDGE-SET-001`, P4, and P7 remain `in_progress`.
