# File > Export project MIDI...

Linux REAPER 7.82 / Default 7 exposes Main action 40849 as `File: Export project MIDI...`, with no default shortcut. The native File menu and export settings were probed in an isolated REAPER profile; the configuration dialog screenshot is [menu-export-midi-native-dialog.png](fixtures/menu-export-midi-native-dialog.png), and the menu label/order appears in [menu-file-native.png](fixtures/menu-file-native.png). Probe details and the screenshot SHA-256 are recorded in [menu-export-midi-native.tsv](fixtures/menu-export-midi-native.tsv).

The native defaults are SMF type 1 (multitrack), PPQN 960, with the optional tempo/meter-change, SMPTE-offset, and marker controls unchecked. REAPER still writes the project's starting tempo and time signature when tempo/meter changes are unchecked. The marker mode defaults to markers; cues and filtering to names beginning with `#` are optional when the project has markers. In the empty reference project, all marker controls were disabled because there were no markers.

AAADAW now opens a dedicated export settings window from the File menu and Action List. It supports type 0 and type 1 files, PPQN conversion, optional tempo/meter and SMPTE metadata, marker or cue-point events, and the `#` name filter. Marker controls stay disabled when the project has no markers, matching the reference. `Export hidden markers` is enabled only when markers exist and marker export is checked; export omits markers hidden individually or by the project marker ruler by default. The option includes ruler-hidden markers in Type 0 and Type 1, while individually hidden markers are included only in Type 1, matching the observed REAPER 7.82 behavior. Encoding runs from a project snapshot in a background task and atomically replaces the chosen destination. Core tests cover type 0/1 headers, default options, track/event data, exact native marker and cue files, marker visibility filtering, PPQ scaling, tempo ramps, and metadata.

The updated desktop binary now links and runs under Xvfb. To work around the missing GLib development package metadata on this host, the build used local pkg-config entries and links under ignored `target/` that point at the installed runtime libraries; no system packages were changed.
