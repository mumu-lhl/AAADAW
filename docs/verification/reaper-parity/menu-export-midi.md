# File > Export project MIDI...

Linux REAPER 7.82 / Default 7 exposes Main action 40849 as `File: Export project MIDI...`, with no default shortcut. The native File menu and export settings were probed in an isolated REAPER profile; the configuration dialog screenshot is [menu-export-midi-native-dialog.png](fixtures/menu-export-midi-native-dialog.png), and the menu label/order appears in [menu-file-native.png](fixtures/menu-file-native.png). Probe details and the screenshot SHA-256 are recorded in [menu-export-midi-native.tsv](fixtures/menu-export-midi-native.tsv).

The native defaults are SMF type 1 (multitrack), PPQN 960, with the optional tempo/meter-change, SMPTE-offset, and marker controls unchecked. REAPER still writes the project's starting tempo and time signature when tempo/meter changes are unchecked. The marker mode defaults to markers; cues and filtering to names beginning with `#` are optional when the project has markers. In the empty reference project, all marker controls were disabled because there were no markers.

AAADAW now opens a dedicated export settings window from the File menu and Action List. It supports type 0 and type 1 files, PPQN conversion, optional tempo/meter and SMPTE metadata, marker or cue-point events, and the `#` name filter. Marker controls stay disabled when the project has no markers, matching the reference. `Export hidden markers` is enabled only when markers exist and marker export is checked; by default export omits markers hidden individually or by the project marker ruler, while the option includes them. Encoding runs from a project snapshot in a background task and atomically replaces the chosen destination. Core tests cover type 0/1 headers, default options, track/event data, exact native marker and cue files, marker visibility filtering, PPQ scaling, tempo ramps, and metadata.

The updated desktop binary now links and runs under Xvfb. To work around the missing GLib development package metadata on this host, the build used local pkg-config entries and links under ignored `target/` that point at the installed runtime libraries; no system packages were changed. The captured AAADAW File menu, default dialog, and post-export status are [menu-export-midi-aaadaw-menu.png](fixtures/menu-export-midi-aaadaw-menu.png), [menu-export-midi-aaadaw-dialog.png](fixtures/menu-export-midi-aaadaw-dialog.png), and [menu-export-midi-aaadaw-exported.png](fixtures/menu-export-midi-aaadaw-exported.png). The live dialog window measured 520×298. Its default Type 1/PPQN 960 settings produced a 39-byte format-1 MIDI file with one conductor track; `file` identified it as Standard MIDI format 1, and its SHA-256 matched the earlier live export. The `cargo test ... export` app filter passed 34 tests, including both MIDI dialog and empty-project marker regressions. Stable Clippy with `-D warnings`, rustfmt check, and `git diff --check` also passed. The build and screenshot environment, binary identity, MIDI hash, and screenshot hashes are in [menu-export-midi-native.tsv](fixtures/menu-export-midi-native.tsv).

The screenshot comparison shows that AAADAW's dialog matches the native dialog's measured 520×298 window geometry, and marker controls are disabled in the empty-project case. The new model persists per-marker and ruler-lane visibility, and the core export test verifies visible-only default output plus inclusion when `Export hidden markers` is enabled. The REAPER probe confirmed the same behavior for both individually hidden markers and a hidden marker lane; its dialog and output measurements are recorded in [marker visibility evidence](fixtures/marker-visibility-native.tsv) and [selected marker evidence](fixtures/marker-visibility-selected-native.tsv). The dark surface and control styling still differ from REAPER's light-gray dialog. The File menu still lacks native entries such as New project tab, Project templates, Region Render Matrix, and Consolidate/Export tracks, so its full order is not aligned yet. `FILE-MIDI-EXPORT-001` and `SHELL-MENU-KEYBOARD-001` remain `in_progress`.

### REAPER 7.82 type-1 and type-0 event comparisons

The [native ReaScript probe](../../../scripts/reaper_parity/probe-midi-export-content.lua) creates a fresh unsaved project with one `Piano` track and a MIDI item from 0.25 to 1.25 seconds. The item contains a C4 note at project ticks 480–1440, CC1 value 64 at tick 720, and pitch bend 12288 at tick 840. It opens Main action 40849; the isolated REAPER dialog exports type 1 at PPQN 960 with the optional metadata checkboxes left unchecked. The script records both take-local and project-timeline PPQ coordinates in [the probe manifest](fixtures/menu-export-midi-native-content.tsv).

The 119-byte native MIDI file and its SHA-256 are checked in as [the native binary fixture](fixtures/menu-export-midi-native-content.mid). It contains two tracks: a conductor track named after the destination file stem, with 4/4 and 120 BPM at tick 0, and `Piano`, with the exact four channel events and End-of-Track at tick 1440. AAADAW previously omitted the mandatory start tempo/meter, used a generic conductor name, and ended the MIDI track at the item boundary. The encoder now matches the native fixture byte-for-byte; the export app derives the conductor name from the output path. `reaper_782_type_one_export_matches_native_track_and_event_bytes` locks this comparison, and `conductor_track_name_uses_the_export_destination_stem` checks the app path handling.
