# MIDI Contents Nudge on REAPER 7.82

Linux REAPER `7.82/linux-x86_64` with `Default_7.0.ReaperThemeZip` was opened in a fresh, unsaved project with transport stopped. The probe created one selected five-second MIDI item at 2 seconds, with notes at source PPQ 960–2880 and 4800–6720. The real Nudge/Set window was set to Nudge, Target `contents`, and 250 milliseconds; the captured [dialog](fixtures/item-nudge-midi-contents-native-dialog.png) shows the Snap checkbox enabled.

With Snap disabled, Main action 41249 changed the take's `D_STARTOFFS` from 0 to 4.75 seconds. Action 41250 then changed it to 0, and another left Nudge changed it to 0.25 seconds. A second fresh project repeated those actions with Snap enabled and produced the same offsets. All cases retained the item at 2 seconds with length 5 seconds, retained `B_LOOPSRC=1` and selection, and left the raw note PPQ positions unchanged. REAPER's project state-change counter remained unchanged. Exact values are in the [native fixture TSV](fixtures/item-nudge-midi-contents-native.tsv); the disposable [ReaScript probe](../../../scripts/reaper_parity/probe-item-nudge-midi.lua) drives the actions through the actual dialog settings.

This constant-tempo probe verifies the observed MIDI take-offset and loop-boundary behavior for the tested 250 ms cases. Variable-tempo behavior is recorded separately below. The MIDI-only probe does not establish every source length, source-section behavior, or Undo/Redo semantics. During that probe, `Undo_CanUndo2` returned inconsistent labels across actions and a keyboard Undo could not be isolated from the audio-device modal; Undo is therefore left open.

AAADAW now stores `loop_source` and a fixed MIDI source loop length in project snapshots and SQLite schema 51. Existing projects migrate by inferring the source length from the visible item length and stored event extent. A 5-second/9600-tick MIDI source at 120 BPM now wraps a 250 ms right Contents Nudge from tick offset 0 to 9120; Undo restores 0 and a left Nudge reaches 480. For a clip starting at a 60 BPM tempo point, the same 250 ms duration converts to 240 ticks, verified by `item_nudge_midi_contents_converts_time_using_the_item_tempo_map_position`. The item bounds and stored event PPQ remain unchanged. The loop iterator feeds the realtime event plan, arrangement preview, and standard MIDI export; the audio callback remains allocation-free. Core, storage migration/round-trip, engine schedule/export, and application Nudge tests cover this path. Absolute Set → Contents for a looped MIDI item is separately implemented and compared with a native 2-second item / 3-second target probe; see [Set Contents verification](item-nudge-midi-set-contents.md).

The MIDI Editor now renders and source-edits repeated note, CC, and pitch-bend loop occurrences; the native and AAADAW window screenshots plus focused tests are recorded in [MIDI Editor loop-source verification](midi-editor-loop-source.md). AAADAW now applies MIDI Contents Nudge with the Snap checkbox either on or off; this matches the native probe, where both settings produced the same source offsets. A focused app test covers the enabled setting. Audio and MIDI items can now be moved together by one Contents Nudge transaction; app regressions verify both offsets change together, Undo/Redo are atomic, and a missing audio source fails without changing the MIDI item. A Linux REAPER 7.82 mixed-selection probe confirms one 250 ms right Contents Nudge moves an Audio loop offset 0.1→9.85 seconds and a MIDI loop offset 0→4.75 seconds; a left Nudge returns both, and one Undo/Redo cycle restores and reapplies both offsets together. Item bounds, selection, and MIDI note PPQ remain unchanged. The [native fixture](fixtures/item-nudge-mixed-contents-native.tsv), [dialog screenshot](fixtures/item-nudge-mixed-contents-native-dialog.png), and [probe script](../../../scripts/reaper_parity/probe-item-nudge-mixed-contents.lua) record this case. The observed state-change counter stayed at zero for direct Nudge actions and advanced once for Undo and Redo; this single mixed sequence does not establish deeper undo-history behavior.

For a stepped variable-tempo case, Linux REAPER 7.82 had 120 BPM at project start and a 60 BPM point at 4 seconds. A five-second MIDI item starting at 3.9 seconds crosses that point 100 ms after its start. With Target `contents`, 250 ms, and Snap off, the 250 ms wall-clock interval maps to 336 PPQ across the tempo point, but native action 41249 moves the loop source by 480 PPQ, using the tempo at the item's start. The source offset then reports 4416 PPQ in a 4896 PPQ loop; action 41250 returns to the loop endpoint (equivalent to phase zero). The two MIDI note events and item bounds remain unchanged, and the project state-change count stays zero. The [native TSV](fixtures/item-nudge-midi-variable-tempo-native.tsv), [configured dialog](fixtures/item-nudge-midi-variable-tempo-native-dialog.png), [post-Nudge dialog](fixtures/item-nudge-midi-variable-tempo-native-after-right.png), and [ReaScript probe](../../../scripts/reaper_parity/probe-item-nudge-midi-variable-tempo.lua) preserve the observation. AAADAW now converts the Nudge duration at the tempo active at the MIDI item's start; its regression expects the native 4416 PPQ result. Linear tempo ramps remain open.

Other open checks include a user-facing MIDI source-loop length control, source-length recovery for old trimmed items, exact linear-tempo source-loop/timebase precision, other tempo curves, and broader Undo semantics. A separate REAPER probe records a 250 ms nudge inside a 120-to-60 BPM linear ramp; action 41249 wrapped source phase by 446.915 PPQ while the matching project-time interval mapped to 298.875 PPQ. AAADAW's linear-ramp regression is within 6.985 PPQ of the native source phase, with the remaining source-loop precision gap documented in [linear-ramp verification](item-nudge-midi-linear-tempo.md). The stepped-point boundary is separately captured in [stepped-tempo verification](item-nudge-midi-stepped-boundary.md), where right Nudge reports 4320 PPQ and left Nudge reaches the 4800 PPQ source-loop endpoint. The MIDI `Loop source` toggle in Item Properties is covered separately in [MIDI Item Properties Loop source verification](midi-item-properties-loop-source.md). Set Contents currently covers absolute targets for looped MIDI with the native Snap-off setting; Snap-on behavior and other media types remain unverified. `ITEM-NUDGE-SET-001` remains `in_progress`.

Validation after the stepped-boundary and linear-ramp MIDI Contents Nudge changes: the targeted App regressions passed 19/19, the complete AAADAW desktop suite 586/586, and Core timebase tests 16/16. Core and App all-target Clippy `-D warnings`, rustfmt, and diff checks passed.
