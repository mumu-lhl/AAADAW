# MIDI Contents Nudge on REAPER 7.82

Linux REAPER `7.82/linux-x86_64` with `Default_7.0.ReaperThemeZip` was opened in a fresh, unsaved project with transport stopped. The probe created one selected five-second MIDI item at 2 seconds, with notes at source PPQ 960–2880 and 4800–6720. The real Nudge/Set window was set to Nudge, Target `contents`, and 250 milliseconds; the captured [dialog](fixtures/item-nudge-midi-contents-native-dialog.png) shows the Snap checkbox enabled.

With Snap disabled, Main action 41249 changed the take's `D_STARTOFFS` from 0 to 4.75 seconds. Action 41250 then changed it to 0, and another left Nudge changed it to 0.25 seconds. A second fresh project repeated those actions with Snap enabled and produced the same offsets. All cases retained the item at 2 seconds with length 5 seconds, retained `B_LOOPSRC=1` and selection, and left the raw note PPQ positions unchanged. REAPER's project state-change counter remained unchanged. Exact values are in the [native fixture TSV](fixtures/item-nudge-midi-contents-native.tsv); the disposable [ReaScript probe](../../scripts/reaper_parity/probe-item-nudge-midi.lua) drives the actions through the actual dialog settings.

This verifies the observed MIDI take-offset and loop-boundary behavior for the tested 250 ms cases. It does not establish tempo-map conversion, every source length, source-section behavior, or Undo/Redo semantics. During the probe, `Undo_CanUndo2` returned inconsistent labels across actions and a keyboard Undo could not be isolated from the audio-device modal; Undo is therefore left open.

AAADAW now stores `loop_source` and a fixed MIDI source loop length in project snapshots and SQLite schema 51. Existing projects migrate by inferring the source length from the visible item length and stored event extent. A 5-second/9600-tick MIDI source at 120 BPM now wraps a 250 ms right Contents Nudge from tick offset 0 to 9120; Undo restores 0 and a left Nudge reaches 480. For a clip starting at a 60 BPM tempo point, the same 250 ms duration converts to 240 ticks, verified by `item_nudge_midi_contents_converts_time_using_the_item_tempo_map_position`. The item bounds and stored event PPQ remain unchanged. The loop iterator feeds the realtime event plan, arrangement preview, and standard MIDI export; the audio callback remains allocation-free. Core, storage migration/round-trip, engine schedule/export, and application Nudge tests cover this path.

The full behavior is still open. The MIDI Editor does not yet render/edit repeated loop occurrences, loop source has no user-facing toggle or dedicated source-length control, source length recovery for old trimmed items is inferred, tempo-map conversion has only an AAADAW regression and still needs a REAPER variable-tempo comparison, and Undo semantics have not been confirmed against REAPER. Snap remains unsupported for Contents Nudge, as do mixed Audio/MIDI selections. `ITEM-NUDGE-SET-001` remains `in_progress`.
