# MIDI Editor Event List

Reference: Linux REAPER 7.82, Default 7 theme. MIDI Editor action 40056 switches to Event List and is bound to Alt+3; Alt+1 returns to Piano Roll. The native capture shows the event table columns `Index`, `Position`, `Length`, `Channel`, `Type`, `Parameter`, `Value`, `Off Value`, and `REAPER Data`. It also displays a synthetic terminal `(end) All Notes Off` row, including when the MIDI item has no stored events. The repeatable probes record both the four-note item and the empty-item case; readbacks, native screenshots, and AAADAW real-window captures are listed in the [fixture manifest](fixtures/midi-event-list-ui.tsv).

AAADAW now exposes Piano Roll and Event List modes in the MIDI Editor and Action List. Event List presents modeled Notes, Control Change, Pitch Bend, Program Change, Poly Aftertouch, and Channel Pressure entries in project BBT positions, with note lengths, one-based channels, parameter/value fields, and off values. When CC0 and CC32 share a tick and channel, it presents them as one `Bank Select 14-bit (0/32)` row whose value is `(MSB × 128) + LSB`; clicking, keyboard-selecting, or deleting that row acts on both stored controller events. Program Change rows show the effective bank and program tuple in Parameter and the zero-based program in Value. Non-Note rows leave Length and Off Value blank. A real-window [Bank Select capture](fixtures/midi-event-list-bank-program-aaadaw.png) shows CC0=12, CC32=23, and Program Change 42 as `1559` and `12-23-42`; selecting and deleting the bank row removes both controllers, leaves the PC at `0-0-42`, and Undo restores the row and tuple. The [case manifest](fixtures/midi-event-list-bank-program-aaadaw.tsv) records the stable desktop build, reusable project generator, and screenshots.

Event List appends `(end) All Notes Off` at the item length as a synthetic cursor row, not a stored or exported MIDI event. An empty item therefore shows one row at its end; the row can be selected and navigated to, and Delete/Backspace leaves the project unchanged. Delete on a modeled row removes that event. Real-window captures verify the empty row, the populated row, no-op deletion of the terminal row, and deletion of a real note. Note rows display persistent MIDI Note Off velocity in `Off Value`; the native and AAADAW fixture uses Note On 91 / Note Off 37 and verifies the displayed 37 in Event List and Event Properties. Apply changes it to 42, and Undo/Redo restore 37/42. See the [note-off velocity fixture manifest](fixtures/midi-note-off-velocity-ui.tsv). REAPER 7.82 displays a Program Change's raw zero-based program number in the Value column. Poly Aftertouch uses the native pitch name (for example `C4`) in Parameter; Channel Pressure has no parameter. Native REAPER and real-window AAADAW captures and readbacks for both pressure event types are in the [aftertouch fixture manifest](fixtures/midi-aftertouch-ui.tsv). The native type filter offers `<all events>`, Note, Poly Aftertouch, Control Change (CC), Program Change (PC), Channel Pressure, Pitch, and the combined `Sysex/Meta` category. Native and AAADAW screenshots confirm that Sysex/Meta includes track-name, text, marker, and SysEx rows; the inverse hides those opaque rows and shows channel events together with `(end) All Notes Off`, which is a non-Sysex/Meta event. Direct Sysex/Meta filtering hides the synthetic terminal row. AAADAW applies the same matching to visible rows and keyboard-navigation candidates. See the [type-filter fixture manifest](fixtures/midi-event-filter-ui.tsv). Native REAPER 7.82 also confirms that Control Change filtering accepts a controller parameter and inclusive Value range: selecting CC7 and values 64–100 leaves those two CC7 rows visible. AAADAW models those criteria for Event List rows, CC lanes, and selection operations; the [Parameter and Value comparison](midi-event-filter-parameter-value.md) records the native and current-build evidence. Ctrl/Cmd-click toggles a row, and deleting selected events creates one undoable transaction. The in-memory mode does not alter MIDI project data.

For one or more selected rows of the same modeled type, `Edit event…` and action 40004 (`Ctrl+F2`) open Event Properties; a single selected editable text Meta or SysEx row uses the same entry point. Notes expose absolute Position, Length, Channel, Pitch, Note On Velocity, and Note Off velocity; CC events expose Position, Channel, Controller, and Value; Pitch Bend exposes Position, Channel, and raw 14-bit Value; Program Change exposes Position, MIDI channel, its zero-based Program number, and Bank MSB/LSB backed by CC0/CC32. REAPER opens a dedicated `Bank/Program Select` dialog for a Program Change. Text Meta exposes Text, Type, Multi-line text, and Position; SysEx exposes fixed F0/F7 framing, a hex payload editor, Position, and Load/Save. The implementation maps the nine editable REAPER Meta types and commits opaque edits as one undoable event update while preserving event order. Current-build Linux Xvfb evidence verifies loading two-line UTF-8 Meta text, switching to Marker, committing it and displaying readable lines in Event List; it also verifies a SysEx payload edit and Undo. Apply leaves modeled-event dialogs open after one undoable update; OK commits and closes them; Cancel and Escape discard uncommitted fields. The separate [Event Properties verification](midi-event-properties.md) records the measured native dialogs and AAADAW windows.

Arrow Up/Down now follows the measured row-selection behavior: the first unmodified arrow collapses a multi-selection at its active row, and the next arrow moves to the adjacent visible event. Ctrl+Arrow Up/Down moves the independent Event List cursor while retaining the selected rows. Shift+Arrow Up/Down extends or contracts the selection from its anchor across every visible event row, including mixed Note, CC, and Pitch Bend rows. Home selects the first visible event and moves the project edit cursor to that event's project position; End moves the project edit cursor to the MIDI item's end and leaves the selected event intact. The isolated Linux REAPER 7.82 probe uses an item from 4–8 seconds, a first note at 4.25 seconds, and another item ending at 12 seconds: Home selects that note and moves the cursor 6→4.25 seconds, then End moves it 4.25→8 seconds. The [native trace and screenshots](fixtures/midi-event-list-ui.tsv) record the event-selection bits and cursor readback. AAADAW's current desktop build selects the first visible row on Home and reaches the item end on End; its real-window screenshots show the selected Note and the arrangement cursor readouts at 0.25 and 2 seconds. The [native navigation trace](fixtures/midi-event-list-navigation-native.tsv) records Arrow-key selection bits after each step. In the native Event List, double-clicking a value opens the complete Event Properties dialog rather than editing that cell inline, so direct per-cell editing is not a parity gap.

AAADAW records Event List mouse-row toggles, non-preserving Arrow selection, Shift-range changes, and Home selection in the same app-level history as Piano Roll selection. The snapshot includes every modeled event selection set, Event List cursor and anchor, and the shared Arrange inline note selection. A fresh Cranelift desktop build selected C4, Ctrl-clicked D4, then Ctrl+Z restored C4 alone and Ctrl+Shift+Z restored both rows; project content stayed unchanged. The four current-build captures and test/build details are in the [selection history fixture](fixtures/midi-event-list-selection-history-aaadaw.tsv). A separate Linux REAPER 7.82 / Default 7 Event List probe now confirms that Ctrl-clicking an unselected row enters the same Undo/Redo sequence: Ctrl+Z clears that row's selection and Ctrl+Shift+Z restores it. Saved native RPP readbacks show only the note-selection flags changed; the measured Event List captures and readbacks are listed in the [native selection-history fixture](fixtures/midi-event-list-selection-history-native.tsv).

This is a partial implementation, not full Event List parity. Ctrl+F2 on REAPER's synthetic terminal row opens a blank Event Properties form; AAADAW now opens the matching unset Type/Position/Channel form from the terminal row, including when it is the only visible row and has only the initial visual selection. AAADAW currently renders those fields as display-only; Apply is a no-op, and Apply/OK create no project event. Local App coverage verifies that the project snapshot and history remain unchanged. REAPER's Apply/OK behavior for this blank form is unmeasured. The [current terminal-row view](fixtures/midi-event-list-empty-end-aaadaw-properties-action.png) and [form opened with Ctrl+F2](fixtures/midi-event-list-empty-end-aaadaw-properties.png) are Xorg dummy display captures, not a pixel-diff comparison with REAPER. The nine-column table now includes REAPER Data and supports horizontal scrolling in narrow windows; the current-build [full-width capture](fixtures/midi-event-list-reaper-data-aaadaw.png) and [narrow-window scroll capture](fixtures/midi-event-list-reaper-data-aaadaw-narrow-scroll.png) are listed in the [fixture manifest](fixtures/midi-event-list-reaper-data-aaadaw.tsv). Native captures confirm REAPER Data is blank for Note, Program Change, Poly Aftertouch, and Channel Pressure rows; AAADAW currently leaves all row values blank, while REAPER's Meta/SysEx data display remains unprobed. Unsupported structural Meta rows remain read-only. Filter selection now includes Set/Add/Remove, with native Note/channel 5 behavior, saved RPP readbacks, and current-build AAADAW screenshots in the [filter selection record](midi-event-filter-selection.md); native Set/Add/Remove with Show-only disabled are also confirmed, while other filter combinations remain open probes. Control parameter and Value range criteria are implemented for CC events. Position in measure and Repeat are shared by Note and CC visibility and selection; Position remains open for other event kinds, and Length is still modeled for Notes only. Solo is not implemented, native reset behavior for Control and Value remains unmeasured. Set filter from selection handles homogeneous selected Notes and same-parameter or mixed-parameter CC selections. Mixed parameters disable Control/<all> while deriving inclusive Value and Position ranges. The Event List Filter funnel has its own active state; Set filter from selection can activate the funnel and change Show-only according to the selected event combination; the measured transitions are recorded per case. Enabling Show-only also activates the funnel, and disabling the funnel clears Show-only. Native and current-build evidence is recorded in the [selection-derived filter record](midi-event-filter-from-selection.md) and the [filter-toggle manifest](fixtures/midi-event-filter-toggle-native.tsv). Mixed Note+CC, Note+opaque, CC+opaque, Note+CC+opaque, and Program Change+Channel Pressure+opaque Set-from-selection paths are now measured and implemented; other heterogeneous event-type combinations remain open. The [Program Change + Channel Pressure + opaque record](midi-event-filter-from-selection.md) links native and current-build readbacks, screenshots, and regressions. Clear filter resets the modeled subset and preserves event selection/data as documented in the [Clear filter record](midi-event-filter-clear.md). Mixed-type event properties, horizontal field navigation, sorting/column sizing, and context menus remain open. BBT is currently derived from the project meter and PPQ without REAPER source-offset/loop-occurrence display semantics. Mode persistence between editor closes or application restarts has not been established. These differences keep `MIDI-EVENT-LIST-001`, UI-019, and P7 `in_progress`.

The initial layout screenshots use a two-note AAADAW project and the four-note native probe. The new navigation captures use that native probe and an AAADAW project with CC, Pitch Bend, and two Notes. The terminal-row captures use an empty item and a four-note item, matching REAPER's end position at `3.1.00`; they are real-window behavior evidence, not a pixel-diff comparison. Automated App tests cover mode shortcuts/commands, empty and populated item terminal rows, mixed event ordering and channel filtering, BBT formatting, event selection and navigation, Delete routing/no-op behavior, one-step event deletion, Undo and Redo.

The newest Set-from-selection probe covers Program Change + Poly Aftertouch + Text Meta together. REAPER derives All events, All channels, shared Position and Repeat measure, enables Show-only and the funnel, shows seven in-range rows, and restores all ten rows when the funnel is disabled. AAADAW matches these states and retains all three selected endpoints; the [native](fixtures/midi-event-filter-from-program-poly-aftertouch-opaque-selection-native.tsv) and [AAADAW](fixtures/midi-event-filter-from-program-poly-aftertouch-opaque-selection-aaadaw.tsv) manifests record the real-window screenshots, readbacks, MIDI data, project fixture, and regression. The Position decimal fields remain visibly different from REAPER's combo boxes, and full Event List acceptance stays `in_progress`.
