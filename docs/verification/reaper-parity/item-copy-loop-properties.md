# Audio item loop-copy properties

This slice extends `ITEM-AUDIO-COPYLOOP-001` with property-level copy/paste behavior. The probe ran REAPER 7.82 for Linux x86_64 with Default 7, an isolated profile, a stopped transport, and a generated 10-second WAV. The script and raw result are recorded in [the native fixture](fixtures/item-copy-loop-properties-native.tsv).

With a 3–7 second time selection and a source item set to item volume 0.5, fade-in 0.5 seconds, fade-out 0.75 seconds, Take volume 0.25, Take pan 0.5, and Take playrate 1.25, REAPER's Copy loop (40014) followed by Paste items/tracks (42398) created a 4-second item at 12 seconds. It retained item volume, Take volume, Take pan, and Take playrate; both fades were zero. The copied source section began at 3.75 seconds and was 5 seconds long, reflecting the active Take rate. The complete-item and start-edge cases in the same probe also pasted with zero fades while retaining the tested mix values.

AAADAW now records item volume, active Take volume/pan, and playback rate in its project-local audio clipboard. A dedicated insertion action creates the looped item and applies those values as one atomic, undoable transaction. The app regression checks two differently mixed items across copy, paste, Undo, Redo, a second paste, and track offsets. For the native 1.25x case, copied source offsets and lengths now include the Take rate while the pasted timeline length remains unchanged. New items receive zero fades, matching the probed REAPER result.

The related [Take-name probe](fixtures/item-copy-loop-name-native.tsv) found that REAPER appends ` loop` when pasting a named Take, leaves an empty name empty, and does not append the suffix a second time when copying a Take already named with that suffix. The fixture displays an empty raw field as `(empty)`; the original ReaScript output SHA-256 is recorded in the fixture manifest. AAADAW's clipboard now follows that naming rule and inserts the copied name in the same atomic transaction as the item and mix.

Audio Take playback rate now persists in Core snapshots and SQLite schema 57, appears in Audio Item Properties, and feeds the realtime and offline decoder/resampler path. A 1 kHz source rendered through a 1.25x item produces the expected 1.25 kHz output, and the copy/paste regression checks the native 3–7 second selection mapping to 3.75–8.75 seconds. A live AAADAW properties window displays a loaded 1.25x rate; [the fixture](fixtures/audio-take-rate-properties-aaadaw.tsv) records its window size and exact binary/screenshot hashes. Apply/Undo/Redo behavior is covered separately by an app regression. This is AAADAW-only evidence and does not compare pixels or interaction to REAPER. The resampler currently converts the effective source rate to an integer number of hertz, so arbitrary fractional rates can be quantized slightly; pitch-preserve mode and native rate-range behavior are not represented. The clipboard remains project-local and rejects selections that cross an already-looped source boundary. Broader native/AAADAW window comparisons remain open. The native property probe itself has no screenshot.
