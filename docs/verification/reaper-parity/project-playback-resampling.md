# Project playback resampling

Reference: Linux REAPER 7.82, Default 7 theme, fresh factory configuration. The General page's factory playback mode is `Sinc Interpolation: 64pt (medium quality)`; render mode is `Sinc Interpolation: 192pt`. The [native dropdown capture](project-settings-ui/reaper-native-playback-resampling-options.png) records all eleven playback choices and their order. The machine-readable factory values are in [project-settings-general-reference.json](../../reaper-parity/project-settings-general-reference.json).

AAADAW's media worker uses a 64-tap, Blackman-windowed sinc interpolator for playback and a 192-tap filter for WAV export and Freeze. Both use normalized phase tables when source and project rates differ; the anti-alias cutoff follows the output/input rate ratio, and equal-rate streams copy PCM directly. When source metadata provides a rate, the worker builds or reuses its coefficient table before reporting ready, so startup does not leave the playback queue waiting on filter setup. Decoding and filtering remain on the cancellable worker thread, which feeds the existing bounded PCM queue with backpressure. The audio callback does not allocate or calculate resampling coefficients.

Focused checks cover constant-level preservation, output duration, chunk-boundary invariance, stereo channel separation, and 48 kHz to 24 kHz spectral behavior: a 3 kHz playback passband tone remains above 0.97 amplitude, the 18 kHz tone's 6 kHz alias remains below 0.01, and a 13 kHz transition-band alias is lower with the render filter. The application-level queue test exercises both qualities through real media workers; the file-backed item test covers trim and sample-clock placement. Full workspace validation ran under Xvfb.

These paths use the measured factory filter lengths, not REAPER's verified coefficient-for-coefficient kernel. The General selector and project persistence are still absent; point, linear/IIR, other sinc lengths, and r8brain modes are not implemented. Pitch shifting and stretch-marker settings are separate unimplemented behavior. The Project Settings matrix therefore remains `in_progress`.

Transport Repeat accepts unequal source/project rates only when the repeated segment boundaries map to exact source frames; its worker warms sinc history for periodic Loop playback. When an already-active trimmed item has a linear prefix before Loop, both equal-rate handoff and bounded rate-converted handoff are verified. Rate-converted prefix handoff now uses the Loop start as prefix-filter right context and seeds the repeated filter with cyclic samples from the Loop tail, so the first and later passes produce identical PCM. Decoded Loop segments up to 1 MiB use a bounded cache. Larger rate-converted loops use a bounded-memory history pre-scan: the worker reads only as far as the cyclic tail history, then signals readiness and reopens the source to stream the prefix and Loop segment. It subsequently reopens at the Loop source start for each repeated pass. This keeps full-loop PCM out of memory and the callback remains free of decoder I/O. The tradeoff is longer playback preparation for long or compressed sources. A worker-level regression compares two complete passes from a >1 MiB decoded stereo Loop with an independently seeded cyclic resampler; this verifies internal cycle consistency, not native filter-kernel equivalence.
