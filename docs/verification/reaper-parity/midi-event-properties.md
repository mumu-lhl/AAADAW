# MIDI Event Properties

Linux REAPER 7.82 / Default 7 uses MIDI Editor action 40004, `Edit: Event properties`, in MIDI Event List section 32061, with `Ctrl+F2`. With one Note selected, the native window exposes Type, BBT Position, BBT Length, Channel, Note, Velocity, Off value, and OK/Cancel/Apply. A disposable-profile ReaScript creates a selected note at tick 720 with length 240, channel 3, pitch 60, and velocity 91, then opens the Event List and action 40004. REAPER displays `1.1.75`, `0.0.25`, `3`, `60 C4`, `91`, and off value `0`. The reproducible script, event readback, and native/AAADAW screenshots are listed in the [fixture manifest](fixtures/midi-event-properties-ui.tsv).

AAADAW registers `Edit: Event properties` with the native Ctrl+F2 shortcut and opens it from the Event List for exactly one selected note. Position and Length accept absolute `bar.beat.hundredths`; Channel accepts 1–16; Pitch accepts MIDI numbers or note names such as `C♯4`; Velocity accepts 0–127. Apply commits a single existing `EditMidiNotes` transaction and refreshes the dialog, OK commits and closes, and Cancel/Escape discard draft values. Invalid BBT and model values leave the draft open with feedback. The current-build [AAADAW desktop capture](fixtures/midi-event-properties-aaadaw.png) verifies the actual editor window and dialog layout; the native reference crop is [here](fixtures/midi-event-properties-native.png).

This does not complete native Event Properties parity. Only one Note event can be edited. CC and Pitch Bend properties, multiple selected events, direct keyboard-relative `+`, `-`, `*`, `/` values, the `+1o` octave syntax, and persistent note-off velocity are not implemented. The project model currently stores no note-off velocity, so the dialog reports that Off value is not modeled. Event Properties BBT editing uses the project PPQ and meter at tick zero; meter-map changes, source offsets, and loop-source occurrences still need native probes. `MIDI-EVENT-PROPERTIES-001`, `MIDI-EVENT-LIST-001`, UI-019, and P7 remain `in_progress`.
