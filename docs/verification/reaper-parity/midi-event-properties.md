# MIDI Event Properties

Linux REAPER 7.82 / Default 7 uses MIDI Editor action 40004, `Edit: Event properties`, in MIDI Event List section 32061, with `Ctrl+F2`. With one Note selected, the native window exposes Type, BBT Position, BBT Length, Channel, Note, Velocity, Off value, and OK/Cancel/Apply. A disposable-profile ReaScript creates a selected note at tick 720 with length 240, channel 3, pitch 60, and velocity 91, then opens the Event List and action 40004. REAPER displays `1.1.75`, `0.0.25`, `3`, `60 C4`, `91`, and off value `0`.

The native CC probe selects controller 7 at tick 480, channel 3, value 90. REAPER displays Position `1.1.50`, Channel `3`, Controller `07 Volume MSB`, Value `90`, CC shape `Square`, Bezier tension `0.00`, and OK/Cancel/Apply. The probe script, readback, and cropped native screenshot are listed alongside the Note evidence in the [fixture manifest](fixtures/midi-event-properties-ui.tsv).

The native Pitch Bend probe selects raw value `9000` at tick 480, channel 3. REAPER displays Type `Pitch`, Position `1.1.50`, Channel `3`, Value `9000` with the centered offset `(+808)`, CC shape `Square`, Bezier tension `0.00`, and OK/Cancel/Apply. The isolated-profile probe and cropped screenshot are in the same manifest.

The native Program Change probe inserts a `0xC0` event at tick 480 on channel 3 with raw program value `41`. Event List shows Type `PC` and Value `41`; action 40004 opens `Bank/Program Select` with MIDI channel `3`, Bank MSB/LSB `0` / `0`, and Program number `41`. This confirms that the displayed Program number is zero-based (0–127). The native Event List screenshot, dialog screenshot, and ReaScript event readback are listed in the [Event List fixture manifest](fixtures/midi-event-list-ui.tsv).

AAADAW registers `Edit: Event properties` with the native Ctrl+F2 shortcut and opens it for a homogeneous selection of one or more Notes, CCs, Pitch Bends, or Program Changes. Fields with different values are blank; leaving a mixed field untouched preserves each event's existing value. Notes accept absolute `bar.beat.hundredths` Position/Length, Channel 1–16, MIDI pitch numbers or names such as `C♯4`, Note On Velocity 0–127, and persistent Note Off velocity 0–127. The Note Off field matches the native `Off value` control and the Event List `Off Value` column. Native and AAADAW captures use velocity 37; editing it to 42 with Apply, then Undo/Redo, verifies values 37/42 in the actual Event List. The [note-off velocity fixture manifest](fixtures/midi-note-off-velocity-ui.tsv) records the probe, project, screenshots, binary identity, and readbacks. CC events accept Position, Channel 1–16, the editable named-controller combo, and Value 0–127. Pitch Bend accepts Position, Channel 1–16, and raw Value 0–16383; the dialog also displays the offset from center value 8192. Program Change accepts Position, MIDI channel, raw Program number 0–127, and Bank MSB/LSB values backed by channel CC0/CC32 events. Patch-file selection and exact native bank edit behavior are not yet verified. Apply commits one undoable event update and refreshes the dialog, OK commits and closes, and Cancel/Escape discard draft values. Invalid BBT and model values leave the draft open with feedback. The [Note desktop capture](fixtures/midi-event-properties-aaadaw.png), [CC desktop capture](fixtures/midi-event-properties-cc-aaadaw.png), and [Pitch Bend desktop capture](fixtures/midi-event-properties-pitch-bend-aaadaw.png) are real AAADAW Xvfb window screenshots. Separate CC and Pitch Bend captures document the applied values and Undo/Redo results.

The current Linux desktop build also opens a selected Program Change in the `Bank/Program Select` dialog. Its initial value 41 matches REAPER's zero-based display; applying 42 updates the Event List, then Undo/Redo restores 41/42. The initial dialog and the applied, undone, and redone rows are captured in the [Event Properties fixture manifest](fixtures/midi-event-properties-ui.tsv). Bank MSB and LSB read the effective values of CC0 and CC32 at each selected Program Change (defaulting to 0), and edits add or replace those channel events at the edited Program Change position. The Program Change and bank updates are committed together in one project transaction, invalidate the compiled playback graph, and schedule CC0/CC32 before a same-tick Program Change; Apply/Undo/Redo regression coverage checks inherited bank values, same-tick replacement, and invalid-value rejection. A current-build [AAADAW window capture](fixtures/midi-event-properties-bank-program-aaadaw.png) shows the added fields beside REAPER's native [Bank/Program Select capture](fixtures/midi-event-properties-program-select-native.png).

A Linux REAPER 7.82 / Default 7 interactive probe now verifies the edit itself: changing Bank MSB/LSB and Program from `11/22/41` to `12/23/42`, then clicking OK, reads back CC0=`12`, CC32=`23`, and PC=`42` at tick 480 on channel 3. REAPER Event List presents the same-tick CC pair as one `Bank Select 14-bit (0/32)` row with value `1559` (`12 × 128 + 23`) and displays the Program Change parameter as `12-23-42`, with value `42`. The before/after ReaScript readbacks, initial/edited native dialog, and resulting Event List screenshot are in the [Event Properties fixture manifest](fixtures/midi-event-properties-ui.tsv) and [Event List fixture manifest](fixtures/midi-event-list-ui.tsv). AAADAW's native bank edit semantics now have both automated and interactive A/B evidence; its Event List still needs to group paired CC0/CC32 rows and show the bank tuple beside Program Change. Patch-file selection, mixed event-type properties, and full view alignment remain open.

Native REAPER multi-selection probes use two selected events of each modeled type. Position, Channel, Note, Velocity, Length, Controller, and Value are blank where selected values differ; CC shape and Bezier tension remain `Square` and `0.00` when common. Native input probes confirm that `+10` applies per event (velocity 90/100 becomes 100/110) and that `+1o2` adds 14 semitones to each selected note (pitch 74/78 becomes 88/92). The native windows also state that fields accept relative `+`, `-`, `*`, `/` inputs and that octave syntax uses `+1o2`. The input/result screenshots, readbacks, and reusable selection probe are listed in the [fixture manifest](fixtures/midi-event-properties-ui.tsv).

A separate native REAPER probe confirms that Position `+0.1.00` advances each selected event by one beat: notes at `1.1.25` and `1.1.50` move to `1.2.25` and `1.2.50` (240/480 to 1200/1440 ticks at 960 PPQ in 4/4). The entered field and resulting Event List are captured in the same fixture manifest. This verifies the relative BBT addition syntax for the default meter; meter-map, source-offset, and loop-source cases still need probes.

AAADAW accepts `+`, `-`, `*`, and `/` in numeric event fields, applying the operation to each selected event's own value. Position/Length fields accept relative BBT offsets for addition/subtraction and numeric factors for multiplication/division. Note pitch also accepts octave syntax such as `+1o2`. Each batch remains one undoable operation; edits that would exceed the channel, pitch, velocity, controller, bend, position, or length ranges are rejected without changing any selected event. App regression tests cover the four operators across Notes, CC, and Pitch Bend, mixed-value preservation, octave conversion, bounds, and Undo. Real AAADAW window captures show note Velocity 96/100 +10 → 106/110 and C6/G4 +1o2 → D7/A5, plus CC 7/90 +1/+10 → CC 8/100 and Pitch Bend 9000 /2 → 4500; Undo restores the original values. The selected inputs, applied event rows, and Undo captures are all listed in the [fixture manifest](fixtures/midi-event-properties-ui.tsv).

The aftertouch probe adds both REAPER event types to the same dialog flow. Poly Aftertouch exposes Position, Channel, Note, and Value; Channel Pressure exposes Position, Channel, and Value. The native properties windows and Event List readback are compared with real AAADAW windows in the [aftertouch fixture manifest](fixtures/midi-aftertouch-ui.tsv). The AAADAW capture applies Poly Aftertouch value 37→42, closes the dialog, then verifies the Event List Undo/Redo values 37/42. The project model still does not store CC shape or Bezier tension, so both controls are clearly marked as not modeled.

Opaque event properties are now available for one selected SysEx or editable text Meta row from `Edit event…` and action 40004 / Ctrl+F2. The native 7.82 SysEx window has fixed F0/F7 framing, a multiline hexadecimal payload area, Position, Save/Load, OK, and Cancel. AAADAW exposes the payload as a multiline hex editor, preserves framing when committing, and provides `.syx` / `.sysex` Load and Save actions. The native text Meta window has Text, Type, Multi-line text, Position, Load, OK, and Cancel; its Type list contains Text event, Copyright notice, Track name, Instrument name, Lyrics, Marker, Cue, Program name, and Device name. The implementation maps those nine Meta kinds and commits text, type, multiline content, and Position in one undoable `SetMidiOpaqueEvents` action while preserving event order; regression tests cover this path but remain unexecuted because the test binary could not be built after the workspace filesystem filled. The current AAADAW screenshots confirm the dialog layouts. In a live Xvfb probe, clicking Type, Multi-line, and Load did not visibly change the dialog, so direct UI editing and Meta file loading remain unverified. Invalid hex and out-of-range BBT values are covered in the test code. The paired native and AAADAW captures, probe MIDI file, binary identity, and regression-test names are in the [Event Properties fixture manifest](fixtures/midi-event-properties-ui.tsv).

The final Linux desktop build also verifies the named CC combo: searching `10` presents `10 Pan MSB`, selecting it and applying changes a CC7 event to CC10, and Undo restores CC7. The search dropdown, selected option, applied row, and Undo row are captured from the actual AAADAW window and tied to build SHA-256 `eef64c2bf8fc0099bec151f52eb85cfb409bbe516d5500b6fb275080539f0a6b` in the fixture manifest.

This does not complete native Event Properties parity. Meta type/text/multiline/load interactions need repair and live verification; mixed-type selections, patch-file selection, SysEx file-dialog read/write behavior, invalid UTF-8 Meta editing, F7 continuation packets, and exact type/text control focus remain open. CC shape and Bezier tension remain absent from the project model. Event Properties BBT editing uses the project PPQ and meter at tick zero; meter-map changes, source offsets, and loop-source occurrences still need native probes. CC named values are available through the editable combo, though its search/focus details still need a closer native comparison. `MIDI-EVENT-PROPERTIES-001`, `MIDI-EVENT-LIST-001`, UI-019, and P7 remain `in_progress`.
