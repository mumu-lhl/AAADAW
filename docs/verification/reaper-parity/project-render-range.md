# Project WAV render bounds

Reference target: Linux REAPER 7.82, Default 7 theme, fresh factory configuration. This record proves AAADAW's current output behavior; it does not claim factory UI or behavior parity where the native render dialog has not yet been captured.

The Render window currently offers `Entire project`, `Time selection`, `All project regions`, and `All project markers` bounds, a tail duration with up to millisecond precision, Mono/Stereo output channels, and an output-rate picker. The captured REAPER 7.82 Bounds menu also lists `Custom time range`, `Selected regions`, and `Selected markers`; those three choices are not implemented yet. Tail input is parsed as decimal seconds without floating-point conversion and converted to the nearest project sample. A time selection is converted from its start-inclusive/end-exclusive tempo-map ticks to project samples when the user starts the render. The rate picker offers the project rate or the eleven explicit rates measured in General Project Settings: 8,000, 11,025, 16,000, 22,050, 32,000, 44,100, 48,000, 88,200, 96,000, 176,400, and 192,000 Hz. The offline queue stores the sample bounds, tail duration, channel count, concrete output rate, format, and Master ceiling in the job, so later selection or control changes do not retarget queued work.

`All project regions` queues one output job per project region. Each job freezes that region's start-inclusive/end-exclusive sample range, the selected Render source, output format, rate, channels, tail, and normalization settings. Output names use the chosen filename as a prefix followed by the sanitized region name; duplicate region names receive a numeric suffix. Multi-output work renders into a private staging directory and publishes only after every render completes. Existing destinations, cancellation, and render failures do not leave a partial output set. This batch mode is currently disabled on Android because its document picker only supports a single output destination.

`All project markers` queues one output job for each marker. A marker starts its half-open range and the next marker ends it; the final marker extends to the last media item's project end. The name prefix uses the sanitized marker name, with a two-digit zero-padded marker number when its name is empty, matching REAPER's `$marker` wildcard, and a numeric suffix for duplicates. The same grouped staging and cancellation rules apply. Native UI and WAV captures confirmed three markers produce three files spanning `[0,2)`, `[2,4)`, and `[4,5)` seconds. Extending a region to 8 seconds while media ends at 5 seconds did not extend the final marker output. An unnamed marker 3 rendered as `03` in the filename. See [the marker fixture](fixtures/render-markers-ui-native.tsv), [the native Bounds menu](fixtures/render-all-markers-menu-native.png), [the three-file UI capture](fixtures/render-all-markers-count-native.png), and [the unnamed-marker fixture capture](fixtures/render-all-markers-unnamed-native.png); the longer-region endpoint probe is [captured here](fixtures/render-all-markers-project-end-native.png).

Native comparison used a 48 kHz stereo PCM24 source with one-second items and matching regions at `[0,1]`, `[2,3]`, and `[4,5]`. Selecting `All project regions` in the actual Render dialog produced `bounds-ui-Region 1.wav`, `bounds-ui-Region 2.wav`, and `bounds-ui-Region 3.wav`; each is stereo PCM24, 48,000 Hz, and 48,000 frames. The first frame in each is `[0.11824941635, 0.35474824905]` after REAPER's default track pan law. The fixture and native dialog captures are in [the bounds evidence files](fixtures/render-bounds-ui-native.tsv), [the Bounds menu screenshot](fixtures/render-bounds-menu-native.png), and [the three-file button screenshot](fixtures/render-bounds-output-count-native.png). `probe-render-bounds.lua` also records a raw `RENDER_BOUNDSFLAG` setter sweep in [a separate table](fixtures/render-bounds-setter-sweep.tsv); those setter values did not reliably reproduce the UI choice, so the UI selection and resulting files are the semantic reference.

The graph renders at the project rate. When the selected output rate differs, a stateful 192-tap sinc converter runs on the offline worker and writes converted frames to the WAV writer; equal-rate exports bypass the extra converter. Mono output averages the stereo Master mix after conversion. Regression evidence covers 48 kHz to 44.1 kHz, exact output duration, packet-boundary invariance, selected range plus fractional tail, and Mono/Stereo channel headers/data for six linear PCM/IEEE float encodings plus 4-bit IMA ADPCM, 2-bit cADPCM, and G.711 u-Law. Native format menus and PCM8/PCM32/Float64/u-Law/IMA ADPCM/cADPCM outputs are recorded in [Render formats](render-formats.md); native Mono mix evidence for a centered case is recorded in [Render channels](render-channels.md).

Output supports Mono or Stereo; multichannel output remains incomplete. Master mix, selected-track stems, selected tracks via Master, and Master mix plus stems are partially implemented as documented in [Render Source](render-source.md); sample-peak normalization is partially implemented as documented in [Render Normalize](render-normalize.md). Tail precision is limited to milliseconds, and the rate preset list is reused from General rather than verified against the native Render list. Selected regions, selected markers, custom time range, item/Razor bounds, render presets, metadata, loudness normalization, and limiting remain incomplete. The selected-range tail currently continues through later timeline material; that detail and the factory default tail duration still require comparison with REAPER. The captured Bounds menu and region/marker output fixtures do not cover the full Render window, so this atomic item remains `in_progress`.

WAV output is published only after a successful render. Cancellation and source/render errors drop the temporary file; the regression also verifies that an existing destination is unchanged when cancellation is already requested.

Focused evidence:

- `crates/aaadaw/src/app/audio_export.rs`: range controls resolve against the current project tempo map, per-region outputs freeze independent ranges, and missing selections/regions cannot be submitted.
- `crates/aaadaw-app/tests/audio_playback.rs`: a non-zero selection starts on the correct source samples, outputs exactly the selected frame count plus a one-second tail, and keeps the project sample rate/stereo header.
- `crates/aaadaw-app/src/offline_render.rs`: range length validation, distinct range lengths in a grouped render, and cancellation/publication rollback.

The parity matrix and progress record track the remaining native comparison and sample-rate controls separately.
