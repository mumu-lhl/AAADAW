# MIDI Editor selected-note quantize

Linux REAPER 7.82 / Default 7 was probed with an isolated project and action 40469 (`Quantize notes position to grid`). Its default MIDI Editor grid is `1/32` (0.125 quarter notes; 120 ticks at PPQ 960). Three selected notes starting at ticks 100, 350, and 900 move to 120, 360, and 960. The unselected note at tick 550 stays put. Each selected note keeps its 120-tick duration, velocity, pitch, and MIDI channel. The before/after projects, complete event TSV, native editor screenshot, and probe script are listed in the [fixture manifest](fixtures/midi-note-quantize-ui.tsv).

AAADAW adds a `Quantize` command to the desktop MIDI Editor toolbar. It quantizes only the currently selected notes to the editor grid at full strength and records the changes as one undoable project event; note duration, channel identity, and unselected notes remain unchanged. New projects now use the native `1/32` MIDI grid. An explicit grid saved with a project remains its selected value. The [REAPER capture](fixtures/midi-note-quantize-reaper-native.png) shows the native grid and quantized events; the [AAADAW capture](fixtures/midi-note-quantize-aaadaw.png) shows the added toolbar command and `1/32` default. The generated AAADAW project and source generator are included in the fixture manifest.

Core regression checks selected-ID filtering, unselected-note preservation, duration/channel preservation, and Undo/Redo. App regressions verify the quantize command uses the default MIDI grid, its one-step history behavior, and the mapping for every ordinary/dotted/triplet grid division. The complete Quantize dialog, strength settings, quantizing note ends/events, swing behavior, and Humanize remain open; this slice covers REAPER's direct “Quantize notes position to grid” action only.
