# MIDI file import

AAADAW imports Standard MIDI Files from `Insert > MIDI file…`. Parsing runs off the UI thread; a three-option dialog appears after parsing, and confirming applies all selected tracks, Tempo/Meter points, and project markers as one undoable project transaction at the edit cursor. Cancel and Escape leave the project unchanged. The options default to off, matching Linux REAPER 7.82 / Default 7.

The decoder accepts PPQ-timed SMF format 0 and format 1. It validates chunk bounds, VLQs, status/data bytes, declared track counts, and End of Track placement; expands running status; and limits input to 64 MiB, 1,024 tracks, and 1,000,000 events. Format 2 and SMPTE time divisions are rejected. Project conversion scales positions from file PPQ to project PPQ using nearest-tick rounding. Note On/Off, CC, Pitch Bend, Program Change, Poly Aftertouch, Channel Pressure, text/marker Meta, and SysEx are retained. An F7 packet continues only an immediately preceding, still-open F0 message; it is merged into that message and moves the event position to the final packet tick. REAPER closes an unterminated F0 with a synthetic F7 at track end or before another event or F0, and discards an F7 packet with no open F0; project conversion follows those rules while the decoded source track retains each original packet. Repeated notes with the same channel and pitch pair FIFO. An unmatched Note On/Off or a converted note with zero duration rejects the entire import.

The default option set merges source tracks into one item named after the first source track. Enabling `Expand MIDI tracks` separates Type 1 tracks after the leading conductor track; metadata-only source tracks are included. The other options import tempo/time-signature Meta into the project map and Marker/Cue Meta (0x06/0x07) as project markers. Track-name, text, marker/cue, and SysEx events are stored on the MIDI item and shown as navigable rows in the Event List. SQLite schema 63 stores these opaque item events, and SMF export writes retained Meta and SysEx events.

## Linux REAPER 7.82 comparison

The native comparison used a deterministic 212-byte Type 1 file at 960 PPQ with three tracks: a conductor track (120 BPM, 4/4, then 150 BPM and 3/4), a lead track (note, text, CC0/CC32, program change, SysEx and cue), and a metadata-only track (text and marker). The edit cursor was at 2 seconds. The fixture generator, Lua probe, binary fixture, raw event dumps and screenshots are in [`fixtures/midi-file-import-native/`](fixtures/midi-file-import-native/).

REAPER's three `MIDI File Import` options are unchecked by default: expand MIDI tracks, import the tempo map, and import MIDI markers/cues as project markers. With the defaults, REAPER creates one track named `Conductor` with one item at 2 seconds. That item contains events from all three source tracks, including both source track-name events, ordinary text, marker/cue Meta, and SysEx; the project tempo map and project markers are unchanged. With all three options enabled, REAPER creates `Lead` and `Meta only` tracks, applies conductor tempo/meter points at the edit cursor, and imports both marker/cue events as project markers. The MIDI items retain text, marker/cue and SysEx in both modes. The [default import screenshot](fixtures/midi-file-import-native/reaper-7.82-default-import.png), [expanded import screenshot](fixtures/midi-file-import-native/reaper-7.82-expanded-import.png), [options screenshot](fixtures/midi-file-import-native/reaper-7.82-import-options-default.png), and raw event dumps record the results.

A separate Type 0 probe places an F0 packet at tick 240 (`43 12`) and an F7 continuation at tick 480 (`34 F7`). REAPER imports them as one F0 event at tick 480 with raw message `F0 43 12 34 F7`; the SysEx Properties window displays payload `43 12 34`, Position `1.1.50`, and the usual F0/F7 boundary labels. AAADAW's current Linux desktop build now produces the same single Event List row and Properties payload from the same MIDI fixture. Seven additional native fixtures confirm that unmatched F7 packets are discarded, F0 messages are closed at End of Track or before a new F0, and a channel or Meta event ends an open SysEx chain before a later F7 packet. AAADAW project import now applies those rules while the source-file decoder retains the packet stream. The current-build Event List screenshot from the F0/Meta/F7 case shows the normalized F0 row and Meta row, with no separate row for the unmatched F7. Probe readbacks, inputs, screenshots, and test names are listed in the [Event Properties fixture manifest](../verification/reaper-parity/fixtures/midi-event-properties-ui.tsv).

Two Type 0 fixtures with opposite source order at tick 240 record REAPER's same-tick Event List canonicalization. In both `MIDI_GetAllEvts` readbacks, Meta/SysEx events precede channel events, Program Change precedes the other channel events, remaining non-note channel events retain their relative source order, and Note On rows follow them. The reverse fixture confirms this is not a fixed ordering among CC, pitch bend, poly aftertouch, and channel pressure. The paired native and current AAADAW Event List screenshots show the mismatch: AAADAW currently sorts same-tick rows by fixed event class, so it does not match either source sequence. Inputs, raw readbacks, screenshots, Lua probes, and build identity are in the [same-tick order fixture manifest](../verification/reaper-parity/fixtures/midi-file-import-same-tick-order.tsv). This is an open implementation item: preserving it across import, project editing, snapshots, and SQLite reopen requires per-item event-order metadata; a display-only priority adjustment would still fail the reverse fixture.

## Remaining differences

Off-bar time-signature points are snapped forward to the next valid project bar line, matching the native behavior observed in the probe. The Tempo Map option applies conductor tempo and meter data at the edit cursor, while the Marker/Cue option creates project markers; all selected changes remain one undoable transaction.

Parity remains incomplete. AAADAW preserves channel events when the first Type 1 source track is expanded; REAPER's exact behavior for this uncommon channel-bearing conductor-track case is not yet probed. The native default-import readback shows that with Tempo Map disabled, tempo/meter Meta neither changes the project map nor appears in the merged item's Event List; AAADAW follows that behavior. The expanded-track/Tempo-Map-disabled combination still needs a native probe. Opaque event rows can be selected, navigated, filtered under the native combined `Sysex/Meta` Event List type, edited for supported single-row properties, and deleted with Undo/Redo. Same-tick cross-class ordering is not preserved: two opposite-order native probes establish the current REAPER ordering, while the paired AAADAW screenshot confirms its fixed class sort diverges. The project audio playback path does not yet schedule imported SysEx or raw Meta events. Format 2 and SMPTE divisions remain unsupported.

Automated coverage includes format 0/1 parsing, running status, track separation/merging, PPQ scaling, supported event conversion, opaque Meta/SysEx round-trip, malformed input rejection, note pairing, transaction rollback, Undo/Redo, project snapshot restoration, SQLite save/reopen and schema 62→63 migration. Linux REAPER 7.82 behavior is verified with native readback and screenshots. AAADAW's current-build dialog, imported Arrangement and Tempo/Meter result were exercised in a live Xvfb desktop run; screenshot hashes and the exact build are recorded in [`midi-file-import-aaadaw.tsv`](../verification/reaper-parity/fixtures/midi-file-import-aaadaw.tsv). Opaque Meta deletion and Ctrl+Z restoration were exercised in a second live run; the [Event List screenshots](../verification/reaper-parity/fixtures/midi-opaque-event-delete-aaadaw.tsv) record selected, deleted, and restored states. The current Event Properties probe also loads and edits text Meta and SysEx rows after import, including Meta type/multiline and SysEx payload Undo; the paired screenshots and binary identity are in the [Event Properties fixture manifest](../verification/reaper-parity/fixtures/midi-event-properties-ui.tsv). Keep `MIDI-FILE-IMPORT-001`, UI-019 and P7 `in_progress` until SysEx `.syx/.sysex` file workflows, SysEx/Meta playback, imported cross-class same-tick ordering, and remaining format/UI differences are resolved.
