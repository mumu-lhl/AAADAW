# MIDI file import

AAADAW imports Standard MIDI Files from `Insert > MIDI file…`. Parsing runs off the UI thread; a three-option dialog appears after parsing, and confirming applies all selected tracks, Tempo/Meter points, and project markers as one undoable project transaction at the edit cursor. Cancel and Escape leave the project unchanged. The options default to off, matching Linux REAPER 7.82 / Default 7.

The decoder accepts SMF format 0, format 1, and format 2. It validates chunk bounds, VLQs, status/data bytes, declared track counts, and End of Track placement; expands running status; and limits input to 64 MiB, 1,024 tracks, and 1,000,000 events. To match Linux REAPER 7.82, the 16-bit header division is read as unsigned PPQ even when its high bit marks an SMF SMPTE division. A division of `0xE728` is therefore treated as 59,176 PPQ. Project conversion scales positions to project PPQ using nearest-tick rounding and keeps imported MIDI items at least one quarter note long. Note On/Off, CC, Pitch Bend, Program Change, Poly Aftertouch, Channel Pressure, text/marker Meta, and SysEx are retained. An F7 packet continues only an immediately preceding, still-open F0 message; it is merged into that message and moves the event position to the final packet tick. REAPER closes an unterminated F0 with a synthetic F7 at track end or before another event or F0, and discards an F7 packet with no open F0; project conversion follows those rules while the decoded source track retains each original packet. Repeated notes with the same channel and pitch pair FIFO. An unmatched Note On/Off or a converted note with zero duration rejects the entire import.

The default option set merges source tracks into one item named after the first source track. Enabling `Expand MIDI tracks` separates Type 1 tracks after a metadata-only leading conductor track, or expands every independent Type 2 sequence; metadata-only source tracks are included. Format 2 disables the project tempo-map and marker options, as REAPER does. The other options import tempo/time-signature Meta into the project map and Marker/Cue Meta (0x06/0x07) as project markers. Track-name, text, marker/cue, and SysEx events are stored on the MIDI item and shown as navigable rows in the Event List. SQLite schema 63 stores these opaque item events, and SMF export writes retained Meta and SysEx events.

## Linux REAPER 7.82 comparison

The native comparison used a deterministic 212-byte Type 1 file at 960 PPQ with three tracks: a conductor track (120 BPM, 4/4, then 150 BPM and 3/4), a lead track (note, text, CC0/CC32, program change, SysEx and cue), and a metadata-only track (text and marker). The edit cursor was at 2 seconds. The fixture generator, Lua probe, binary fixture, raw event dumps and screenshots are in [`fixtures/midi-file-import-native/`](fixtures/midi-file-import-native/).

REAPER's three `MIDI File Import` options are unchecked by default: expand MIDI tracks, import the tempo map, and import MIDI markers/cues as project markers. With the defaults, REAPER creates one track named `Conductor` with one item at 2 seconds. That item contains events from all three source tracks, including both source track-name events, ordinary text, marker/cue Meta, and SysEx; the project tempo map and project markers are unchanged. With all three options enabled, REAPER creates `Lead` and `Meta only` tracks, applies conductor tempo/meter points at the edit cursor, and imports both marker/cue events as project markers. The MIDI items retain text, marker/cue and SysEx in both modes. The [default import screenshot](fixtures/midi-file-import-native/reaper-7.82-default-import.png), [expanded import screenshot](fixtures/midi-file-import-native/reaper-7.82-expanded-import.png), [options screenshot](fixtures/midi-file-import-native/reaper-7.82-import-options-default.png), and raw event dumps record the results.

A separate Type 0 probe places an F0 packet at tick 240 (`43 12`) and an F7 continuation at tick 480 (`34 F7`). REAPER imports them as one F0 event at tick 480 with raw message `F0 43 12 34 F7`; the SysEx Properties window displays payload `43 12 34`, Position `1.1.50`, and the usual F0/F7 boundary labels. AAADAW's current Linux desktop build now produces the same single Event List row and Properties payload from the same MIDI fixture. Seven additional native fixtures confirm that unmatched F7 packets are discarded, F0 messages are closed at End of Track or before a new F0, and a channel or Meta event ends an open SysEx chain before a later F7 packet. AAADAW project import now applies those rules while the source-file decoder retains the packet stream. The current-build Event List screenshot from the F0/Meta/F7 case shows the normalized F0 row and Meta row, with no separate row for the unmatched F7. Probe readbacks, inputs, screenshots, and test names are listed in the [Event Properties fixture manifest](../verification/reaper-parity/fixtures/midi-event-properties-ui.tsv).

Two Type 0 fixtures with opposite source order at tick 240 record REAPER's same-tick Event List canonicalization. In both `MIDI_GetAllEvts` readbacks, Meta/SysEx events precede channel events, Program Change precedes the other channel events, remaining non-note channel events retain their relative source order, and Note On rows follow them. The reverse fixture confirms this is not a fixed ordering among CC, pitch bend, poly aftertouch, and channel pressure. AAADAW stores typed-event source ordinals on the MIDI item, preserves them through snapshots and SQLite schema 63→64→65, and sorts Event List rows using the native grouping plus those ordinals. Real-window screenshots from the current Cranelift build match both native sequences. Inputs, raw readbacks, screenshots, Lua probes, and build identity are in the [same-tick order fixture manifest](../verification/reaper-parity/fixtures/midi-file-import-same-tick-order.tsv).

A second native probe exports the imported take with REAPER action 40849 using Type 1 / 960 PPQ defaults. Its exported tick-480 order is CC7, Note On, then Note Off; AAADAW now retains the imported Note Off source ordinal and matches the native event bytes for this same-tick group. Editing, quantizing, or humanizing an imported note carries its source-order entry to the updated note data, so its paired Note Off retains its native position through Undo/Redo. Identical overlapping notes keep their individual order entries when edited. CC, Pitch Bend, Program Change, Poly Aftertouch, and Channel Pressure value edits also keep their typed-event source ordinals. The exporter keeps the native Meta/SysEx, Program Change, other-channel, and note-event groups for imported items. The native input, output, screenshots, and probe script are recorded in the [same-tick Note Off export manifest](../verification/reaper-parity/fixtures/midi-file-export-same-tick-note-off.tsv).

A native Format 2 probe with two independent sequences at 960 PPQ confirms both dialog paths: the default merges both sequences into one item named after the first sequence, with each sequence starting at tick zero; enabling expansion creates one item and track per sequence, keeping the original names and events. The tempo-map and project-marker controls are disabled for this format. AAADAW now decodes Format 2, merges by default, expands all source sequences when requested, and disables those two options. The 84-byte input, raw `MIDI_GetAllEvts`/note readbacks for both paths, and REAPER screenshots are archived in [the Format 2 fixture bundle](../verification/reaper-parity/fixtures/midi-file-import-format-2.tsv).

A Linux REAPER 7.82 probe imports the `0xE728` high-bit division fixture and reads Note On at source tick 250 as project time `0.0021123428` seconds; tick 750 reads as `0.0063370285` seconds. `MIDI_GetPPQPosFromProjTime(0.25)` returns 29,588, exactly half of the effective 59,176 PPQ division. This confirms REAPER treats this nominal 25 fps / 40 ticks-per-frame division as unsigned PPQ. AAADAW follows that measured behavior: at project PPQ 960, source ticks 250 and 750 map to project ticks 4 and 12, and the imported item has the native one-quarter-note minimum length. Probe script, input, API readback and hashes are recorded in [the high-bit division fixture manifest](../verification/reaper-parity/fixtures/midi-file-import-smpte.tsv).

Imported F0/F7 SysEx events are now compiled into sample-accurate CLAP MIDI SysEx events. The in-process processor references immutable plan bytes directly; isolated CLAP requests copy them into a fixed shared-memory area, so audio callbacks do not allocate. A request/block can carry up to 16 KiB of SysEx data. The fixture CLAP instrument verifies the event bytes and sample offset through both routes. Raw Meta events have no plugin playback representation, and external physical MIDI output does not yet send SysEx.

## Remaining differences

Off-bar time-signature points are snapped forward to the next valid project bar line, matching the native behavior observed in the probe. The Tempo Map option applies conductor tempo and meter data at the edit cursor, while the Marker/Cue option creates project markers; all selected changes remain one undoable transaction.

Parity remains incomplete. AAADAW preserves channel events when the first Type 1 source track is expanded; REAPER's exact behavior for this uncommon channel-bearing conductor-track case is not yet probed. The native default-import readback shows that with Tempo Map disabled, tempo/meter Meta neither changes the project map nor appears in the merged item's Event List; AAADAW follows that behavior. The expanded-track/Tempo-Map-disabled combination still needs a native probe. Opaque event rows can be selected, navigated, filtered under the native combined `Sysex/Meta` Event List type, edited for supported single-row properties, and deleted with Undo/Redo. Same-tick import order now matches both opposite-order native Event List probes, survives SQLite reopen, and matches REAPER's paired Note Off order for the exported tick-480 fixture group. Broader import/export edge cases remain open. Imported SysEx now reaches in-process and isolated CLAP instruments at its scheduled sample, subject to the isolated 16 KiB request limit; raw Meta has no plugin playback path, and physical MIDI output SysEx is still unsupported. REAPER's SMPTE-division handling is unusual; AAADAW matches the measured 7.82 unsigned-PPQ interpretation rather than SMPTE wall-clock timing.

Automated coverage includes format 0/1/2 parsing, running status, track separation/merging, PPQ scaling including high-bit divisions, the one-quarter-note minimum item length, supported event conversion, opaque Meta/SysEx round-trip, malformed input rejection, note pairing, transaction rollback, Undo/Redo, project snapshot restoration, SQLite save/reopen and schema 62→63→64→65 migrations. The core import, export, and storage integration suites pass 175/175, including Format 2 default merge/expansion, high-bit division handling, and a byte-for-byte comparison of the native tick-480 channel events.
