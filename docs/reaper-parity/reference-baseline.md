## 证据格式

每条证据包含 `evidence_id`、矩阵 ID、参照版本与配置指纹、环境、fixture、初始状态、输入序列、终态、观察结论、截图/录屏/结构摘要、采集日期和执行者。图像标明客户端区域及系统边框范围；音频标明输出路径、帧数、校验和和比较指标。

同一 fixture 在 REAPER 和 AAADAW 中表达等价内容，不要求两者文件二进制一致。ID、临时路径、线程时间和播放动画先建立比较规则；遮罩只能覆盖明确的动态/系统区域，不能遮罩不一致控件。

证据命名示例：`LNX-782-ARR-001-01`。AAADAW 截图和结果进入 `docs/verification/reaper-parity/` 或该唯一 PR 的 CI artifact；记录版本与稳定链接。REAPER 内部参照图片保留来源及访问位置，不作为产品素材，不将安装包或默认主题资源提交到仓库。

- [官方下载](https://www.reaper.fm/download.php)：2026-10-09 调研时列出 7.82；实施仍固定 7.82。

- [官方主题开发资料](https://www.reaper.fm/sdk/walter/walter.php)：用于理解布局与状态，不意味着主题素材可直接分发。

历史架构中的“默认 14 按钮”、快捷键表、64 通道上限等均是待复核线索；只有实际证据才可进入规范值。手册、代码、旧设计和运行结果不一致时，将差异记入矩阵并以固定参照实测为准。

## 平台、资源与范围边界

Linux 原厂全部适用入口属于主验收范围。Windows/macOS 专属后端和格式单独记录同版本平台项；不要求在 Linux 提供无意义的平台入口。Android 保持原有触控、生命周期和工程互通，不以缩小桌面界面实现触控。

第三方插件内部 GUI 以同插件为准；AAADAW 负责宿主外壳、嵌入/浮动、焦点、参数和状态。原厂自带插件及其窗口另列条目。算法替代、主题细节或协议限制必须显示为具体差异；未批准的差异不算通过。

图标、控件和视觉几何由项目实现；保留 AAADAW 品牌。未经授权的 REAPER 二进制、Logo、图标、截图和主题资源不进入产品。需额外获取的合法资源或协议条件作为具体技术阻断项处理，不引入与任务无关的审批流程。

SWS/ReaPack/第三方脚本/用户主题不是原厂基线，单独登记。原厂脚本、视频、网络和控制器界面仍在计划内；不能以“高级功能”将其排除。
